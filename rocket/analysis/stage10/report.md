## 注意点(結果を読む前に)

1. **S2 の値は、どのシャッフルを引いたかで大きく変わる。** D の乱数ごとの AUC は 0.602〜0.607 とほぼ一定ですが、S2 は S2a 0.524〜0.679、S2b 0.509〜0.689 と幅があります。このばらつきは、カーネルの乱数ではなくシャッフルによるものです。10通りのシャッフルでは、シャッフルの分布を十分に代表しているとは限りません。「差がある」の基準は分割による揺れだけを見ていて、シャッフルによる揺れを含んでいません。
2. **S2 の帰無分布は D より狭い。** 帰無分布の AUC の標準偏差は、D 0.061、S1 0.067 に対して、S2a 0.043、S2b 0.046 でした。S2 の統計量は、10通りの**違う入力**(シャッフル)での平均なので、置換ごとの値が平均で打ち消し合い、幅が狭くなったと考えられます。そのため95%点も低く(S2a 0.569、D 0.595)、S2a の「当たっている」は D と同じ厳しさの判定ではありません。S2a の AUC 0.578 は、D の95%点 0.595 よりは低い値です。置換も D の1000回に対して200回です。
3. **alpha の張り付きが S2 では緩い。** D は100%の fold で上限でしたが、S2a 56%、S2b 74% でした。シャッフルした入力では、Ridge の正則化の選ばれ方が D と違います。
4. 入力は段階6と同じ `stage4/main_X.npy` です。開花日を新しい `flower_date` 列(EXP-016 の予測)に切り替えた入力ではありません。

## 解釈(事前に決めた表との対応)

| | 判定 | 事前の表で当てはまる行 |
|---|---|---|
| S1 | 偶然の水準 | – |
| S2a | 当たっている(注意点2)、D と差なし | 「偶然の水準 / D と差なし」→ 順番は要らないが、8つの要約統計では捉えられない分布の情報を MiniRocket が拾っている |
| S2b | 偶然の水準、D より低い(差あり) | 「偶然の水準 / D より明らかに低い」→ 時間の並び方 (b) に情報がある |

**S2a と S2b で当てはまる行が違い、表にはきれいに当てはまりません。** 無理に一つの結論にはまとめず、わかったことを書きます。

- **(a) 変化の大きさは、8つの要約統計では表せなかった。** S1 は偶然の水準(AUC 0.517、p=0.38)で、D より 0.088 低い(記述的な比較)。日々の変化の大きさ・極値・増減の総量だけでは、D の精度は出ません。
- **時間の並びを壊すと、AUC は下がる方向にそろった。** D − S2a +0.027、D − S2b +0.043 で、どちらも正です。S2b では差の基準を満たしました(繰り返しの100%で正)。S2a は基準に届きませんでした(85%)。
- **それでも、並びを壊した入力が偶然の水準に落ち切ったとも言えない。** S2a は(狭い帰無分布に対してですが)95%点を超え、S2b も p=0.085 です。シャッフルによっては D 以上の値(0.679、0.689)も出ています。
- **S2a と S2b の違いからは、「日のそろい方」と「隣り合う日のつながり」のどちらが効いているかは言えない。** S2a − S2b は +0.016 で、差は検出できませんでした(85%)。仮に日のそろい方(開花後の何日目か)が効いているなら、それを残した S2b の方が高くなるはずですが、点推定では逆(S2a の方が高い)です。ただし、この差は検出できていないので、解釈しません。

まとめると、**1次差分の情報は、8つの要約統計で表せる変化の大きさ (a) だけでは説明できません。時間の並びを壊すと AUC は下がる傾向があり (b) を支持します。ただし、並びを壊しても情報が一部残っている可能性があります(8つの要約統計に入らない値の分布の情報)。** (a) と (b) を完全には切り分けられませんでした。主な原因は、S2 の結果がシャッフルの引き方で大きく揺れることです(注意点1)。

## 判断が必要な点

1. **S2a の「当たっている」をどう扱うか。** 決めた基準では満たしていますが、帰無分布が D より狭いことによる部分があります(注意点2)。このレポートでは、判定を表に書いたうえで、結論の根拠には使っていません。
2. **シャッフルの揺れをどう扱うか。** 「D − S2b の差がある」は、この10通りのシャッフルでの結果です。シャッフルを増やして確かめるかどうか(下の提案1)。

# 時間の順番の置換検定(シャッフルの分布の中での D の位置、EXP-019)

- 日付: 2026-11-05
- スクリプト: `analysis/stage10/run_shuffle_null.py`(この PC、28並列で689秒)
- 出力: `rocket/outputs/stage10/shuffle_null/`(`shuffle_scores.csv` シャッフルごとの AUC・bacc、`shuffle_pvalues.csv`、`kernel_corr_S2a.csv` / `kernel_corr_S2b.csv`、`shuffle_null_hist.png`)
- 目的: 上の S2 は、シャッフルの引き方で AUC が 0.51〜0.69 と揺れ、10通りでは D との比較が定まらなかった。カーネルの乱数を固定してシャッフルを増やし、並びを壊した場合の AUC の分布の中で、本当の並び(D)がどこにあるかを見る

## 設定

| 項目 | 値 |
|---|---|
| データ・分割・モデル・alpha | 上の S2 と同じ(main 82件の1次差分、段階6と同じ分割、MiniRocket(10000)→ StandardScaler(with_mean=False)→ RidgeClassifierCV(logspace(−3, 3, 10) × n_train)) |
| カーネルの乱数 k | 0、1、2(それぞれ別に分布を作る) |
| シャッフル s | 0〜199 の200通り。S2a は `default_rng([1, s])` から82系列を行の順に `permutation(59)`、S2b は `default_rng([2, s]).permutation(59)`。s はカーネルの乱数と独立で、どの k でも同じ200通りを使う |
| 各シャッフルの値 | 20回の繰り返し平均の AUC と bacc。ラベルの置換検定は行わない |
| 統計量(事前に決定) | 片側の p = (1 + D 以上だったシャッフルの数) / (1 + 200)。D は同じカーネルの乱数での本当の並びの AUC(段階6の保存済みの値) |
| 判断(事前に決定) | 3通りの k すべてで p < 0.05 → 時間の並び方に意味がある。それ以外 → 効果は確認できなかった。S2a・S2b のそれぞれで判断する |

**確認**: 段階6と同じ分割: True。上の S2 は s = k の組なので、(k, s) = (0, 0)・(1, 1)・(2, 2) の6つの値(S2a・S2b)が、上の乱数ごとの AUC と完全に一致することを確かめた。

参考(判断には使わない):

- bacc では、D(0.545)はシャッフルの分布のほぼ真ん中だった(シャッフルの平均 0.547〜0.550、p = 0.44〜0.51)。
- 同じシャッフルでのカーネルの乱数の間の AUC の相関は 0.995〜0.997。カーネルの乱数による違いはほとんど無く、AUC はシャッフル(入力)でほぼ決まる。3通りの k はほぼ同じ検定を3回したことになる。
- alpha が上限の fold の割合は、シャッフルの平均で 0.64〜0.66(D は 1.00)。

## 解釈

- 本当の並び(D、AUC 0.605)は、並びを壊したときの AUC の分布の上位約20%に位置する。並びを壊しても、5回に1回は D 以上の AUC が出る。**このデータでは、D の AUC は時間の並び方によるものと示すことはできなかった。**
- **上の EXP-018 の「D − S2b に差がある」はこの結果で置き換わる。** EXP-018 の基準は、分割による揺れだけを見ていて、シャッフルによる揺れを含んでいなかった。10通りで引いた S2b の平均(0.562)は、200通りの平均(0.573)より低めだった。
- シャッフルした入力の AUC の平均(S2a 0.563、S2b 0.573)は、0.5 や、上の S2 のラベル置換の帰無分布の平均(0.49〜0.50)より高い。日の順番によらない情報(値の分布)を MiniRocket が拾っている可能性を示す。ただし、この検定は時間の並びについてのもので、シャッフルした入力自体が偶然の水準を超えるかは調べていない(ラベルの置換をしていない)。記述にとどめる。
- 上の S1(8つの要約統計)は偶然の水準だったので、これが正しいなら、その情報は8つの要約統計では表せない分布の形にあることになる。上の提案3(分位点などを足した S1)で確かめられる。

## 判断が必要な点

1. 段階6の実験D(AUC 0.605)の結論の書き方。「1次差分 + MiniRocket は偶然の水準を超える」(ラベルの置換検定)は変わらないが、「時間の並びを捉えている」とは言えない、と書き添えるかどうか。
2. 次の実験を、値の分布の情報(上の提案3)に進めるかどうか。
