## 設定

| 項目 | 値 |
|---|---|
| 設定 | MR_diff(段階6の実験D)、R0 / R1 / R2 の PPV のみ・PPV + max(段階7・8)。特徴量は StandardScaler(with_mean=False) まで同じ |
| 分割・乱数 | 段階6〜8と同じ 5分割 × 20回(100 fold)。カーネルの乱数は 0 のみ |
| alpha の候補 | logspace(−3, 6, 19) × n_train(評価では logspace(−3, 3, 10) × n_train、上限 1000 × n_train) |
| 出した値 | GCV(LOO の2乗誤差の平均)、LOO 正解率・AUC、実効自由度 df(α)、テストの AUC・bacc、α→∞ の参照分類器(w = Xcᵀyc)|
| 置換 | 市町村×年の中で50回(置換 i は乱数 [0, i]) |

**確認(すべての設定の最初の fold)**: GCV の値は sklearn の `cv_results_` と一致(相対差 ≤ 7e−16)。元の候補で選ばれる alpha と決定関数は RidgeNTrain と一致。LOO 予測値は、1件ずつ抜いて学習し直した値と一致(alpha 3通り、差 ≤ 3e−12)。

## 結果

### 1. GCV の曲線: ほぼすべての fold で単調に下がり続け、切片だけのモデルの値に近づく

| 設定 | GCV 最小が広げた候補の上端(10⁶) | 元の上限(1000)より大きい | 内側で最小 | 内側の最小の深さ(上端との差、最大) |
|---|---|---|---|---|
| MR_diff | 88% | 96%(3% が 1000、1% が 316) | 12% | −0.012 |
| R0_ppv | 49% | 96% | 51%(主に 3162〜10⁴) | −0.026 |
| R0_ppvmax | 72% | 100% | 28% | −0.021 |
| R1_ppv / R1_ppvmax / R2_ppv | 100% | 100% | 0% | − |
| R2_ppvmax | 89% | 100% | 11% | −0.009 |

- GCV は alpha が小さいところで 1.35〜1.96(本当のラベル)。そこから alpha とともに下がり、すべての設定で **1.031** に近づく。1.031 は「切片だけのモデル」(全件の平均で予測)の LOO の2乗誤差 (n/(n−1))² の平均(1.0315)と同じ。
- 内側で最小になる fold も、最小の位置はほとんどが 1000 × n_train より上で、深さは最大でも 0.03 程度(GCV の値の約2%)。曲線はほぼ平らで、最小ははっきりしない。
- **置換したラベルでも同じ形**(上端が 80〜92%)。上限に張り付くのは、本当のラベルに特有のことではない。
- MR_diff では、本当のラベルの GCV は置換の平均より低い(alpha / n = 0.001 で 1.35 vs 1.55、1000 で 1.057 vs 1.078)。ラベルと関係のある成分はあるが、2乗誤差で見ると切片だけのモデルに勝てるほどではない。

### 2. LOO の正解率・AUC: 下向きの偏りがあり、GCV と同じ物差しにならない

- LOO の正解率は、どの設定・どの alpha でも 0.5 を下回る(MR_diff で 0.48 → 0.22)。LOO の AUC は、alpha が大きくなると **0 に近づく**。置換したラベルでも同じ(0.35 → 0)。
- これは LOO の性質による(推測ではなく、式から出る): 切片を学習し直すと、抜いた1件のラベルと逆向きに学習データの平均がずれる。予測が切片だけに近づくほど、LOO 予測値は自分のラベルと逆向きに並ぶ。ラベルが市町村×年の中で釣り合うように付いているので、この効果がそろって出る。
- このため、「GCV の最小と LOO 正解率の最大のずれ」は、そのままでは読めない。本当のラベルと置換の平均の差で見ると、MR_diff では LOO AUC の差が alpha によらず約 +0.10〜+0.11 で、ほぼ一定だった。

### 3. 実効自由度 df(α)

| 設定 | df(1000 × n_train)の中央値 |
|---|---|
| MR_diff | 4.5 |
| R0_ppv / R0_ppvmax | 3.1 / 4.9 |
| R1_ppv / R1_ppvmax | 7.2 / 12.4 |
| R2_ppv / R2_ppvmax | 5.1 / 7.1 |

- alpha が小さいところでは df ≈ n_train − 1(約 64)で、ほぼ補間になっている。上限 1000 × n_train でも、df は 3〜12 残る。上限は「何も学習しない」状態ではなく、上位数個の主成分の方向だけを使うモデルになっている。

### 4. テストの AUC と、α→∞ の参照分類器(fold の平均、乱数0)

| 設定 | alpha / n = 0.001 | 1000(評価の上限) | 10⁶ | 参照分類器 w = Xcᵀyc | 置換の95%点(1000 で) |
|---|---|---|---|---|---|
| MR_diff | **0.630** | 0.605 | 0.542 | 0.542 | 0.599 |
| R0_ppv | 0.507 | 0.542 | 0.541 | 0.541 | 0.584 |
| R0_ppvmax | 0.502 | 0.523 | 0.542 | 0.542 | 0.583 |
| R1_ppv | 0.463 | 0.478 | 0.456 | 0.456 | 0.635 |
| R1_ppvmax | 0.496 | 0.470 | 0.446 | 0.446 | 0.626 |
| R2_ppv | 0.499 | 0.489 | 0.483 | 0.483 | 0.609 |
| R2_ppvmax | 0.555 | 0.535 | 0.530 | 0.530 | 0.596 |

- alpha 10⁶ のテスト AUC は、どの設定でも参照分類器と一致した(極限の確認になっている)。
- **MR_diff**: テストの AUC は alpha / n ≤ 100 で 0.627〜0.630 とほぼ平ら。上限 1000 で 0.605 に下がり、α→∞ で 0.542(クラス平均の差の方向)まで下がる。上限 1000 は、AUC が下がり始めたところにある。
  - ただし、置換の95%点も alpha が小さいほど高い(0.001 で 0.633、1000 で 0.599)。本当のラベルが95%点を超えるのは 1000 付近だけで、alpha を小さくしても「偶然の水準からの離れ方」は大きくならない(乱数0のみ、置換50回。記述のみ)。
- **R0**: alpha が大きいほどわずかに高く、0.54 付近で頭打ち。参照分類器と同じ水準。
- **R1・R2_ppv**: どの alpha でも0.5前後か、それ以下。alpha の選び方では説明できない。
- **テストの bacc**: alpha が大きいと、予測の境目が切片(学習データのクラスの割合)で決まるようになる。MR_diff では、参照分類器を学習データの平均を境に使うと bacc 0.593 だが、alpha 1000 では 0.546。

## 解釈(推測を含む)

- **上限に張り付く直接の理由は、GCV が2乗誤差で alpha を選ぶから。** 約60件・1万列では、小さい alpha の予測値はばらつきが大きく、2乗誤差では切片だけのモデル(1.031)に勝てない。予測値を0に縮めるほど2乗誤差が下がるので、GCV は「縮められるだけ縮める」方向を選ぶ。置換したラベルでも同じ形なので、信号が弱いデータでは当然起きることと考えられる。
- **AUC は予測値の大きさによらない**(並び順だけで決まる)ので、2乗誤差が悪くても AUC は高いことがある。MR_diff で、GCV が最も悪い小さい alpha でテストの AUC が最も高かったのはこのため。GCV の基準(2乗誤差)と評価の主な指標(AUC)が別の物を見ている。
- 上限 1000 × n_train は、テストの AUC を最大にする位置ではない。ただ、置換の95%点との比較では、小さい alpha の方が有利とは言えない。**評価の設定を変える理由にはならない**(設定は変えない方針でもある)。
- R1・R2 が偶然の水準なのは alpha の選び方のせいではない(どの alpha でも 0.5 前後)。段階8の結論は変わらない。
- bacc が AUC に比べて低い一因として、alpha が大きいと予測の境目が切片(クラスの割合)に引っ張られることがありうる(未確認)。

## 判断が必要な点

1. **alpha の扱いをこのままにするか**: 評価の設定は変えないが、論文に書くときに「GCV はほぼ常に上限を選んだ(どの設定でも)」ことと、その理由(2乗誤差で選ぶので、信号の弱いデータでは縮める方向になる)をどこまで書くか。
2. **LOO の正解率・AUC は参考にしない**: 切片の学習し直しによる下向きの偏りがあるため。今後 alpha の選び方を考えるときも、LOO の正解率は基準にしない方がよいと考える。

## 提案(この段階では行っていない)

1. **alpha の選び方を AUC で行う入れ子の CV**(例: 学習データの中を StratifiedGroupKFold で分け、テストの AUC が最大の alpha を選ぶ)。評価の設定を変えることになるので、行うなら別の探索的な実験として、置換検定込みで比べる。
2. **alpha を固定した場合の感度分析**(例: alpha / n = 1、100、1000 を固定し、乱数10通り・置換200回で)。MR_diff で AUC が alpha にどれだけ依存するかを、置換の95%点と合わせて見る。
3. **bacc の境目の問題の確認**: 決定関数から切片を引いて0を境にした bacc や、学習データ内でのしきい値の調整で bacc がどう変わるか。
