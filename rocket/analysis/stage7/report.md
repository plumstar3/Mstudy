## 補足: 学習データ全体の平均・標準偏差で標準化した生の値(乱数0、置換なし)

**想定と違う結果になった。**
- 依頼では「MiniRocket ではほぼ同じ結果になるはず」としていたが、特徴量は大きく変わった。

| 項目 | 値 |
|---|---|
| 特徴量の値が違う割合 | 全 fold の全特徴量の 73% |
| 特徴量の差の最大 | 1.0(PPV が 0 ↔ 1 まで変わる列がある) |
| AUC の差(標準化 − 生の値) | 平均 +0.011、最大 0.24(fold によって −0.17〜+0.24) |
| bacc の差 | 平均 +0.004、最大 0.30 |
| AUC 平均 | 生の値 0.488 → 標準化 0.499(どちらも偶然水準) |
| 選ばれた alpha | 100% の fold で同じ(どちらも上限) |

**原因**(sktime 1.2.0 の `sktime/transformations/rocket/_minirocket_numba.py` を読んで確認。追加の計算はしていない)
- MiniRocket の畳み込みは、系列の端より外を **0 として計算する(ゼロパディング)**。出力の長さは入力と同じ。
  - bias(`_fit_biases`)と変換(`_transform`)の両方とも、この計算になっている。
- カーネルの重みの合計は0(−1 が6つ、+2 が3つ)。9つの点がすべて系列の中に入る位置なら、系列に定数を足しても出力は変わらない。
  - しかし端の位置では一部の点が0として扱われ、重みの合計が0にならないので、**系列の水準(平均)が出力に残る**。
- 特徴量の半分は、端を含む出力全体で PPV を数える。残りの半分は、端を除いた中央部分(`C[padding:-padding]`)だけで数える。
  - ただし bias は、どちらの特徴量でも、端を含む出力全体の分位点から決まる。そのため、中央部分だけで数える特徴量も、bias を通して水準の影響を受ける。
- dilation が大きいと、端にかかる位置が多い。60点の系列では、dilation が大きい組では、端の影響を受けない位置がほとんど残らない。
- 学習データ全体の平均(約0.35)を引くと、この端の部分が変わり、PPV が変わる。
- 正の定数を掛けるだけ(拡大・縮小)なら、bias も同じ倍率になるので、特徴量は変わらない。違いは、平均を引く部分(平行移動)によるもの。
- したがって **sktime の MiniRocket は、拡大・縮小に対しては不変だが、平行移動に対しては不変ではない**。実装の誤りではなく、MiniRocket の作り(ゼロパディング)による。

**意味**
- 生の値を入力にすると、各圃場のセンサーの VWC の水準が、端の部分を通して特徴量に入る。
- **1次差分は、水準(定数のずれ)が差を取った時点で消えるので、この影響を受けない。** 1次差分が生の値より良い理由の1つかもしれない(推測。確かめていない)。

## まとめ

- 1次差分(AUC 0.605)は、生の値(0.492)と z 正規化(0.463)より明らかに高い。AUC の差は乱数10通りすべてで検出された。
- 生の値と z 正規化は偶然水準で、z 正規化は偶然水準をやや下回る。
- 「VWC の水準ではなく、日々の変化の仕方に情報がある」という、段階5以来の見方と合う。
- 交差検証の繰り返しから求めた幅は楽観的になりやすいので、記述的な目安として扱う。

## 判断が必要な点

1. **ゼロパディングによる水準の影響**: 生の値や z 正規化の比較は、パディングの扱いに左右される。パディングをしない(端を使わない)版や、系列の端を折り返す版で比べるかどうか。
2. **z 正規化が偶然水準を下回る理由**: 系列ごとの平均と振れ幅を消すことで、市町村×年の中での相対的な違いが逆向きに学習されている可能性がある(推測)。調べるかどうか。
3. **alpha の上限への張り付き**: 3つの入力すべてで100%。段階6から続いている課題。

### Rocket が1次差分で MiniRocket より低い理由の候補(推測)

- sktime の Rocket の bias は −1〜1 の一様乱数で決まり、データの値の大きさに合わせない(`_generate_kernels`)。
- 今回は `normalise=False` なので、入力の値の大きさはそのまま。
  - 1次差分の値は小さく(SD 0.036、絶対値の95%点 0.08)、生の値も 0.35 ± 0.09 程度。畳み込みの出力に比べて bias が大きすぎ、PPV が0か1に張り付きやすい。
- 列の確認に使った5系列で見ると、**PPV が5系列とも同じ値(全部0か全部1)のカーネルは、1次差分で41%(全部0が21%、全部1が20%)、生の値で37%**だった。82件全体ではもう少し少ないはずだが、系列の違いを表さない列が多い。
- MiniRocket は bias を学習データの畳み込み出力の分位点から決めるので、この問題が起きない。
- ROCKET 原論文は z 正規化した入力を前提にしている(sktime の既定も normalise=True)。今回 normalise=False にしたのは、生の値と1次差分の比較のため(段階6の 0-2 による)。
- その結果、Rocket には不利な条件になった。**max の有無の比較(主な比較)は同じカーネルどうしなので、この影響を受けにくい**が、Rocket と MiniRocket の比較(参考)には効いている。

### まとめ

- **max(global max pooling)を加えても、1次差分・生の値のどちらでも、結果は変わらなかった**(差は検出できなかった)。
- Rocket(PPV でも PPV + max でも)は、どの入力でも偶然水準を上回らなかった。
- 1次差分では、MiniRocket(0.605)が Rocket(0.547)より高い。bias の決め方の違い(データに合わせるかどうか)が効いている可能性がある(推測)。
- 主な設定(MiniRocket・1次差分)は変えない。

### 判断が必要な点

1. **Rocket の bias の大きさ**: normalise=False のままでは、Rocket に不利な比較になっている。
   - 1次差分を系列ごとに z 正規化してから Rocket にかける(normalise=True に相当)版で比べ直すかどうか。
   - ただし、z 正規化は系列ごとの振れ幅の情報を消す。段階7の G2 でも、生の値の z 正規化は悪かった。
2. **max を MiniRocket に加えるか**: 主な比較では効果が見られなかったので、優先度は低いと考える。

### 提案(この段階では行っていない)

1. **MiniRocket に max を加える版**:
   - MiniRocket は、同じカーネル×dilation の組で、bias だけを変えた PPV を複数作る。max はその組の畳み込みの最大値に bias を足しただけなので、標準化すると同じ列になる。
   - そのため max は、カーネル×dilation の組ごとに1列だけ作ればよい(84カーネル × dilation の数。冗長な列は作らない)。
   - 実装には sktime の MiniRocket の内部(畳み込みの出力 C)を使う必要がある。
   - 今回の Rocket では max の効果が見られなかったので、優先度は低い。
2. **Rocket に z 正規化した1次差分を入れる版**(上の判断1)。
3. **sktime の MultiRocket**(PPV・max 以外の pooling(MPV・MIPV・LSPV)も使う)。bias はデータから決めるので、上の bias の問題は起きない。
