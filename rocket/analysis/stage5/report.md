## 設定

| 項目 | 値 |
|---|---|
| 変換 | **sktime 1.2.0** の MiniRocket(num_kernels=10000 → 実際は 9996 特徴量、random_state=0)。参考に ROCKET(Rocket、num_kernels=10000 → 20000 特徴量、random_state=0) |
| 分類器 | StandardScaler(with_mean=False) → RidgeClassifierCV(alphas=logspace(−3, 3, 10))。AUC は decision_function の値 |
| 評価 | `src/evaluation.py`: StratifiedGroupKFold(groups=muniCd) 5分割×20回(シード 0〜19)。同じデータセットの設定は同じ分割 |
| 置換検定 | **すべての設定で200回**(基準線も含む)。市町村×年の中でラベルを並べ替える |
| 判断の目安 | 「当たっている」= 平均が帰無分布の95%点を超え、かつ同じデータセットの最良の基準線を上回る。「差がある」= 20回の繰り返し平均の差の95%以上が同じ符号 |

**指示との違い**
- 変換は aeon ではなく sktime 1.2.0 の実装を使った。
  - aeon を入れると、venv_rocket の scikit-learn・numpy・pandas などの版が変わる(1.6.0 なら scikit-learn 1.5.1 → 1.9.1)。
  - ユーザーと相談し、環境を変えない方を選んだ。
- 変換と Ridge の間に StandardScaler(with_mean=False) を入れた。
  - CLAUDE.md の基本構成で、sktime の `RocketClassifier` の内部構成と同じ。
  - MiniRocket の原論文の実装は `RidgeClassifierCV(normalize=True)` で、こちらも特徴量を標準化している。

**計算の工夫**
- MiniRocket・ROCKET と StandardScaler の fit は、学習データの X だけで決まり、ラベルは使わない。
- 置換検定ではラベルだけが変わり、分割も同じになる。
- そこで、fold ごとの特徴量を一度だけ計算して、置換のたびには Ridge だけを学習し直した。
- 先頭10 fold で、Pipeline(変換 → 標準化 → Ridge)をそのまま回した `evaluate()` と結果が一致することを確かめた。

### (1) 揃え方の比較(実験A、77件・同じ圃場・同じ分割、生の値)

| 変換 | 指標 | 差の平均(main − dap) | 繰り返し平均の差の 2.5〜97.5% | 正の割合 | 判断 |
|---|---|---|---|---|---|
| MiniRocket | bacc | +0.040 | [−0.044, +0.103] | 85% | 差は検出できなかった |
| MiniRocket | AUC | +0.047 | [−0.014, +0.101] | 90% | 差は検出できなかった |
| ROCKET | bacc | +0.061 | [−0.022, +0.136] | 85% | 差は検出できなかった |
| ROCKET | AUC | +0.092 | [+0.026, +0.183] | 100% | 差がある(main の方が高い) |

- どの設定でも、差の向きは main(開花起点)の方が高い。
- ただし、どちらの揃え方も、単独では帰無分布の95%点を超えていない。
- 生の値の入力は実験Bで最も弱かった。「当たっていないモデル同士の差」なので、揃え方の優劣の根拠としては弱い。

### (2) 入力の形の比較(実験B、main 82件、MiniRocket、同じ分割)

| 比較 | bacc の差(正の割合) | AUC の差(正の割合) | 判断 |
|---|---|---|---|
| znorm − raw | +0.007(50%) | +0.011(60%) | 差は検出できなかった |
| **diff − raw** | **+0.074(95%)** | **+0.107(100%)** | **差がある(diff の方が高い)** |
| groupcenter − raw | −0.072(10%) | −0.085(5%) | bacc は検出できず、AUC は差がある(groupcenter の方が低い) |

- **1次差分(diff)だけ**が帰無分布の95%点を上回り、基準線も上回った。
- ただし、超えた幅は bacc で +0.001、AUC で +0.003 しかない。p はどちらも 0.050 で、境界にある。
- diff は、4つの入力の形の中から最良として選んだ値でもある。4つの比較を Holm 法で補正すると、p は 0.2 になる。
- **groupcenter は、テスト集団の入力値(ラベルではない)を使う変換**。同じ市町村×年の集団は必ず同じ側(学習かテスト)に入るので、ラベルのリークは無い。ただし、テスト時に「同じ集団のほかの圃場の VWC」を使う前提になる。
  - main には1件だけの集団が2つあり、その系列は全日0になる。
- 実験Cに使う入力の形は、事前に決めた規則(平均 AUC が最も高いもの)で **diff** になった。bacc の順位でも diff が1位。

| データセット | 件数 | bacc | AUC | 主設定(main diff)との比べ方 |
|---|---|---|---|---|
| main(参考) | 82 | 0.590 | 0.627 | – |
| main_obs | 60 | 0.521 | 0.614 | bacc が下がり、95%点を下回る。AUC はほぼ同じ(p=0.085) |

- 主設定の「境界で当たっている」という結果は、**3つの部分集合のうち2つでは95%点を下回った**。部分集合の取り方で揺れる程度の強さしか無い。
- 灌水ありの12件を除くと上がった。灌水による VWC の変化が、雨による変化と区別できない雑音になっている可能性がある(推測)。

## まとめ

- **「当たっている」と言えるのは、main diff(境界)と main_no_irrigation diff だけ**。主設定の main diff は95%点をわずかに超えただけで、部分集合によって超えたり超えなかったりする。
  - 今の段階では「1次差分を入力にすると、偶然水準を少し上回る兆しがある」までしか言えない。
- 揃え方は、どの比較でも開花起点の方が高い向きだった。差として検出できたのは ROCKET の AUC だけ。
- 入力の形は、1次差分が生の値より良い(差を検出)。z 正規化は生の値と変わらず、集団内中心化は悪い向き(AUC で差を検出)。
- 交差検証の繰り返しから求めた幅は楽観的になりやすい。上の「差がある」は記述的な目安として扱う。

## 判断が必要な点

1. **Ridge の alpha が候補の上限に張り付いている**: 91〜100% の fold で alpha = 1000(上限)が選ばれた。
   - 分類器は、より強い正則化を求めている(特徴量 約1万に対して学習データ 約60件)。
   - 候補の範囲を広げる(例: 10^−3〜10^5)と結果が変わる可能性がある。結果を見た後なので、範囲は変えていない。
2. **境界の p 値**: main diff の p=0.050 は、置換200回では精度が粗い。帰無分布で観測値以上だったのは9回。
3. **MiniRocket の乱数**: カーネルの乱数(random_state=0)は1通りだけで評価した。乱数を変えたときのばらつきは見ていない。
4. **sktime と aeon の違い**: aeon の MiniRocket とは実装が違うので、細部(バイアスの決め方など)で数値が変わる可能性がある。

## 追加の実験の提案(今回は行っていない)

1. **実験A を1次差分で行う**: 揃え方の比較を、当たる兆しのある入力の形でやり直す。今回の比較は、当たっていない生の値どうしだった。
2. **alpha の候補の範囲を広げた再評価**(上の1)。範囲を事前に決めてから行う。
3. **置換の回数を増やす**(例: 1000回): main diff の p を確かめる。
4. **カーネルの乱数を変える**(random_state を5〜10通り): 結果が乱数に左右されないか確かめる。
5. **入力を組み合わせる**: 生の値と1次差分の2チャンネルにする(MultiRocket と同じ考え方)。
6. **`label_year` での比較**: 当初の想定どおり、地域差を拾っていないかを確かめる。
