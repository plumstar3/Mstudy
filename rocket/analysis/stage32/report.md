## 目的

修論の流れを「水分動態の特定 → それを使った分類」に分ける。これまでは「MiniRocket の精度が上がった入力 = 収量に関連する動態」と判断してきた。この段階では、**分類器を学習させずに**、系列そのものを使った検定で次の3つを確かめる。

| 記号 | 動態 | 示唆した段階 |
|---|---|---|
| D | 1次差分による変化量 Δθ(t) | 段階7・13(EXP-009・022) |
| N | 減る動き min(Δθ, 0) | 段階27(EXP-036) |
| N_post | 雨の後(翌日〜3日目)の減少 | 段階29・31(EXP-038・040) |

要約統計(段階10・26)では偶然の水準だったので、系列の形や時間の構造を残したまま検定する。

**位置づけ**: この3つは、同じ119件(とほぼ同じ圃場)に MiniRocket を当てた結果から示唆された仮説である。**この段階は「データから示唆された仮説の、分類器を介さない確認」**で、独立したデータでの検証ではない(double dipping の可能性がある)。

### 実行中に分かった実装の点(パラメータは変えていない)

- **DTW の帯の渡し方**: sktime 1.2.0 の `DtwDist` は docstring では `window` を int(半径)としているが、内部の数値計算は float(系列長に対する割合、半径 = window × 長さ)しか受け付けず、int を渡すと ValueError になる。事前登録の「半径6日」になるように `window = 6/59` を渡し、帯の範囲が max|i − j| = 6 日であることを確かめた(`run_log.txt`)
- **確認**: energy・擬似 F・欠測を含む Welch の t・クラスタ質量を、素朴なループの計算と小さな例で突き合わせ、すべて一致した。各置換で集団ごとのクラス数が保たれることも確かめた。`rain_days`(日1〜59)は Δθ > 0 と完全に一致した

## 考察

### 主の族の判定

**事前に決めた3つの主の検定(A-D、A-N、B)は、どれも Holm 補正の後で多収と低収の差を検出できなかった。** 分類器を介さない検定では、「D・N・N_post が収量に関連する」という仮説を支持する結果は得られなかった。

### 補助・対照の記述

- 対照の A-P は A-D・A-N とほぼ同じ z(0.96〜1.07)で、減る動きと増える動きの違いはこの検定では見えない
- 振幅で正規化した応答曲線では、l = 1〜5 で多収のほうが大きく減る向きが続いた(最大 t = −1.63、p_maxT = 0.29)。段階27・29の向きと同じだが、差は検出できない。この版は補助で、ここから仮説を作り直すと、また同じデータで仮説を作ることになる
- 開花起点の時点ごと(検定C)と DTW(検定D)でも差は検出できなかった

### 「差を検出できない」は「関連が無い」ではない

- 件数は119件(年ごとは78・34・7件)で、とくに年ごとの検定の検出力は低い
- 検定A は1万次元の特徴量すべてに同じ重みを付けた距離を使う。違いが少数の特徴量にしか無ければ、残りの特徴量の揺れに埋もれて検出しにくい(分類器の Ridge は、少数の特徴量に重みを寄せられる)
- 検定B は圃場ごとにイベントを平均した1本の曲線を比べる。イベントの回数・時期・上昇幅との組み合わせ、圃場の中でのイベントごとのばらつきのような情報は、平均で消える

### 段階27・29・31の全体 AUC との対応(参考)

| 入力 | 分類の全体 AUC | この段階の対応する検定 |
|---|---|---|
| D | 段階13 0.607 / 段階31 Dy_D 0.589(Holm 後は上回らず) | A-D: z 1.23、p 0.103 |
| N | 段階27 0.626 / 段階31 Dy_N 0.612(Holm 後は上回らず) | A-N: z 1.06、p 0.125 |
| P | 段階27 0.577(上回らず) | A-P: z 0.96、p 0.135 |
| N_post | 段階29 0.667(旧日平均)/ 段階31 Dy_Npost 0.658(Holm 後 p = 0.0498、境目) | B: T 0.86、p 0.556(正規化版 p 0.294) |

- 分類では N_post が D・N より明らかに高かった(段階31の Dy_Npost − Dy_N +0.046、Holm 後 p = 0.012)。一方この段階では、N_post に当たる応答曲線の検定(B)が主の族の中で最も弱かった。**分類で見つかった N_post の信号は、「雨の後の平均的な減り方の違い」という単純な形では見つからなかった**
- 考えられる理由(どれも推測で、この段階では確かめていない):
  1. 分類器(MiniRocket の N_post 入力)が使ったのは、平均の減り方ではなく、雨の後の日の配置(どの時期に何回雨が来たか)と減少の組み合わせのような、平均の曲線では消える情報である。ただし雨の日の位置 R だけでは偶然の水準だった(段階29、0.428)
  2. 分類の結果は、複数の入力の形を比べた中で選ばれたもので(段階27・29・31)、段階31の Holm 後 p も境目だった。選択による過大評価(double dipping)の可能性がある
  3. 検定A・B の検出力が、教師ありの分類より低い(上の節)
- このため、**「MiniRocket の精度が上がった入力 = 収量に関連する動態」という読み方は、この段階の結果からは裏づけられなかった。** 修論で「水分動態の特定」を独立の結果として書くなら、分類の精度とは別の根拠が要る

### double dipping について

D・N・N_post は、同じ119件(段階29までは旧日平均の123件、共通118件)への分類の結果から作った仮説である。この段階はラベルを使わない変換と置換検定で行ったが、検定する仮説そのものを同じデータから選んでいるので、仮に差が出ていても独立した確認にはならなかった。今回は差が出なかったので、過大評価の向きの問題は結論に影響しないが、「同じデータで仮説を作り、確かめた」という限界は残る。

### 次の検討の候補(ユーザーと相談)

- 分類器がどの情報を使っているかを直接見る(N_post 入力で、雨の日の配置を保ったまま減少の値だけを圃場間で入れ替えるなど)
- 検出力の見積もり(この件数で、どのくらいの差なら検定A・B で検出できるか、シミュレーションで)
- 1時間データから作る日単位の排水の指標(D-009 で候補に残したもの)を、事前に決めた1つの統計量で検定する
