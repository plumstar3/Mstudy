## 1. 共通モジュール `src/windows.py`

| 関数 | 内容 |
|---|---|
| `load_cases()` | `label_muniyear` 付きの94件。DB から開花日の実測値と灌水を付ける(DB は読み取り専用) |
| `load_timeseries()` | VWC 時系列。**収穫日より後の観測は除く**(24行: 362/2017 が18日、557/2017 が6日) |
| `fit_flowering()` | 開花日の推定式 (ii) を、**実測開花日のある66件すべて**で学習する。ラベルは使わない |
| `add_flowering()` | 実測があればそれを、無ければ推定値を使う。`flower_estimated` でどちらかを示す |
| `extract_windows(cases, ts, origin, start, end)` | 起点(`'flower'` = 開花日 / `'sowing'` = 播種日)からの日数 start〜end を切り出す。窓の全日に観測がある件だけ残し、除外した件は理由と一緒に返す |
| `to_raw` / `znorm` / `first_diff` | 入力の形の変換。znorm は系列ごとに平均0・標準偏差1にする。first_diff は60点が59点になる |

- **推定式(最終版)**: 開花 dap = 97.6978 − 0.288942 × 播種日の通日。学習は66件、推定値は整数の日に丸める。`manifest.json` にも記録した。
- 段階3の LOGO 評価(MAE 4.4日)は、この式を地域ごとに学習し直した評価にあたる。

作った列(メタデータに入れた):

- `irr_emergence` / `irr_before_flowering` / `irr_flowering` / `irr_pod_filling`: 区分ごとの0/1。
- `irrigation_day_in_window`: 灌水した日が窓の何日目かは、**日付が無いので求められない**。すべて NaN にした。

## 判断が必要な点

1. **灌水の区分を窓のどこに当てるか**: 「開花期~直後」「莢肥大期」が開花起点で何日目にあたるかは、定義が無い。
   - たとえば、開花期~直後 = 0〜+10日、莢肥大期 = +20〜+40日のように決めて当てはめることはできるが、勝手には決めていない。
2. **灌水を日単位で推定するか**: 気象データの降水量(`weather_data.APCPRA`)を使い、雨が無い日に VWC が急に上がった日を灌水日の候補として推定することはできる。ただし解釈を含むので、行っていない。
3. **灌水ありの件の扱い**: main では12件(多収6・低収6)で、ラベルには偏っていない。段階5でそのまま入れるか、感度分析で除くか。
4. **加古川2016 の極端に低い値**: これまでの決定どおり除外していない。main_no_kakogawa の感度分析で影響を見られる。
5. **dap で1日だけ足りない3件**: 規則どおり除外したが、窓を1日短くすれば入る。比較用の dap の窓を変えるかどうか。
