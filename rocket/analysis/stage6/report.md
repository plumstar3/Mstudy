## 0. 事前確認

### 0-1. alpha の尺度の等価性: **等価**

段階5の main・diff・random_state=0 の MiniRocket 特徴量で、8つの fold と5つの alpha を比べた(`precheck_alpha_equivalence_*.csv`)。比べたのは次の2つ。
- A: 旧 normalize=True を手で再現したもの(学習データで列を中心化し、中心化した列の L2 ノルムで割る。テストにも同じ値を使う)
- B: StandardScaler(with_mean=False)+ alpha × n_train

結果:
- RidgeClassifierCV で選ばれる alpha: 8つの fold すべてで一致した(A の alpha × n_train = B の alpha)。
- 予測: すべて一致した。
- decision_function の差: 最大 3.7×10⁻¹⁵。alpha を固定した RidgeClassifier でも最大 6.8×10⁻¹⁴。どちらも計算誤差の範囲。

出典:
- **scikit-learn の normalize 廃止時の案内**(1.1 系の `sklearn/linear_model/_base.py` の `_deprecate_normalize`)
  - "'normalize' was deprecated in version 1.0 and will be removed in 1.2. … To reproduce the previous behavior: … model = make_pipeline(StandardScaler(with_mean=False), Ridge()) … Set parameter alpha to: original_alpha * n_samples."
  - normalize=True のときの尺度は、同じファイルの `_preprocess_data` で、中心化した列の L2 ノルム(= √n × 標準偏差)として計算されている。
- **MiniRocket の公式実装**(GitHub angus924/minirocket の README)
  - `classifier = RidgeClassifierCV(alphas = np.logspace(-3, 3, 10), normalize = True)`
  - 公開されている例はすべてこの設定だった。

**気づいた点**: 確かめた8つの fold すべてで、**原論文の尺度でも alpha は候補の上限(1000)が選ばれた**。尺度を合わせても上限への張り付きは解消せず、正則化は段階5より強くなる(段階5で選ばれた 1000 は、原論文の尺度で約 15 にあたる)。

### 0-2. sktime の Rocket の既定値: **normalise=True が既定**

| 変換器 | get_params()(sktime 1.2.0) |
|---|---|
| Rocket | `n_jobs=1, normalise=True, num_kernels=10000, random_state=None` |
| MiniRocket | `max_dilations_per_kernel=32, n_jobs=1, num_kernels=10000, random_state=None`(normalise の引数は無い) |

**EXP-007 への補足**(EXP-007 の記録自体は書き換えていない)
- 段階5の実験A の「ROCKET・生の値」(A_RK_main_common / A_RK_dap_common)は、Rocket の既定 normalise=True のために、**実際には系列ごとに z 正規化された入力**だった。
- そのため、「生の値」の MiniRocket と ROCKET は、同じ入力の比較になっていなかった。
- この段階では ROCKET を使っていない。

### 実験D: 確認用の解析(main 82件、diff、置換1000回)

  - 食い違いの一部はしきい値(切片)の問題だと考えられるが、それだけでは説明しきれない。順位づけ(AUC)には少し情報があるが、0 で切る分類としては弱い。

### alpha の張り付き

- F4 以外のすべての設定で、97〜100% の fold で **alpha = 1000 × n_train(候補の上限)** が選ばれた。
- 最も強い正則化で、Ridge の解は「クラスの平均の差の方向」に近い状態になっている(推測)。
- 原論文の設定を正しく移しても張り付きは残るので、これは設定の誤りではなく、データの性質(件数約60に対して特徴量約1万)によると考えられる。

## 3. まとめ(結論として書くのは実験D と実験E だけ)

- **実験D(確認用)**: 事前に決めた基準では、main・diff・MiniRocket の **AUC は偶然水準と基準線を上回った**。
  - AUC 0.605、帰無分布の95%点 0.595、p=0.035(置換1000回)。基準線は 0.483。
  - ただし、超えた幅は小さい(+0.010)。副の指標の bacc(0.544)は95%点(0.562)を下回った。
  - 言えるのは「土壌水分の1次差分の系列には、地域×年の中で多収と低収を順位づける弱い情報がある」まで。
- **実験E(揃え方)**: 1次差分でも、**開花起点と dap の差は検出できなかった**。
  - 向きは10通りの乱数すべてで開花起点が上(AUC +0.055)だが、20回の繰り返し平均で正だったのは85%で、基準に届かない。
  - 共通の77件では、どちらの揃え方も95%点を下回った。
- 交差検証の繰り返しから求めた幅は楽観的になりやすいので、上の数値は記述的な目安として扱う。

## 判断が必要な点

1. **alpha の上限への張り付き**: 原論文の尺度でも残った。候補を上に広げるか、別の正則化(特徴量の数を減らす、別の分類器)を検討するか。どれも事前に設定を決めてから行う。
2. **AUC と bacc の食い違い**: 主な指標を AUC にしたのは事前の決定どおり。bacc を上げたいなら、しきい値の決め方(学習データの中で決める、など)を事前に決めて試す必要がある。
3. **実験E の件数の違い**: main(82件)と main_common(77件)で、AUC が 0.605 → 0.541 と大きく変わる。どの5件が効いているかを見るかどうか。
4. **F4 の対象**: label_year を全202件で評価する場合は、窓を作り直す(段階4のやり直し)必要がある。置換の単位(市町村×年か、年か)も決める必要がある。

## 追加の実験の提案(今回は行っていない)

1. **alpha の候補を事前に決めて広げる**(例: logspace(−3, 6, 13) × n_train): 上限への張り付きが解けたとき、結果が変わるかを見る。

5. **sktime の MultiRocket**(sktime 1.2.0 の `sktime.transformations.panel.rocket.MultiRocket`。既定値は num_kernels=6250、n_features_per_kernel=4、normalise=False): 4種類の pooling を使う本来の MultiRocket と比べる。
