# 段階16: 暦の日付でそろえた集団内中心化

- 日付: 2026-11-09(EXP-025)
- 目的:
  - 同じ市町村×年の圃場は、同じ日に雨が降り、同じ天候の中で乾いていく。この共通の動きは、集団の中の多収・低収の手がかりにならない。
  - 共通の動きを取り除けば、圃場ごとの違い(周りより早く乾く、水が溜まりやすい、など)が残り、地域内 W と全体の AUC が上がる、という仮説を確かめる。
- 経緯(**集団内中心化を試すのは3回目**):
  1. 段階5(EXP-007)の groupcenter(生の値): AUC 0.445。
  2. 段階6(EXP-008)の実験 F2(groupcenter → 1次差分): AUC 0.448。
  - どちらも `label_muniyear` の82件で、開花起点の窓の「何日目か」でそろえて、集団の平均(自分を含む)を引いていた。同じ集団の中でも開花日が違えば暦の日付がずれるので、同じ日の雨の反応がそろわないまま平均を引いていた可能性がある。
  - 今回(3回目)は、**暦の日付でそろえて平均を引き、その後で窓を切り出す**(GC_date)。
  - 段階6の方式を median にかけたもの(GC_index)も参考に並べた。

## 中心化の処理(GC_date)

1. **平均に使う圃場**: 123件が属する28集団の、`soilmoisture_timeseries.csv` にある全圃場×年(142。窓に入らない件・ラベルなしの件19を含む)。
   - 収穫日より後の観測(30行)は除いた。ラベルは使わない。
   - データ全体で、系列が他の圃場と全日同じなのは圃場472・473(2018年)だけで、全日一定の系列は無かった。472・473 の集団(25210_2018)は28集団に入らないので、今回除いた圃場は無い。
2. **平均の取り方**: 暦の日付ごとに、その圃場を除いた同じ集団のほかの圃場の VWC の平均(leave-one-out)を引いた。その日に観測のあるほかの圃場が無い日は NaN にした。
3. **窓**: 中心化した系列から、開花起点の 0〜+59 日(`flower_date`、段階13と同じ日付の範囲)を切り出した。
   - 窓に NaN が入る件は無く、**123件すべてが残った**。件も並びも段階13と同じなので、分割も段階13と同じ。
   - 窓の各日で平均に使ったほかの圃場の数: 最小1、平均4.23。1件だけの日を含む件が2件。
4. **1次差分**: 窓を切り出した後に取った(59点)。

**データの範囲について**: 依頼では「播種日〜収穫日の外のデータは `FieldData_fieldid.db` の `SolidMoisture` にある」とあった。しかし確かめると、CSV にある圃場×年について、DB の行は CSV と完全に同じ30,040行だった(値の差0)。DB にだけある行は、観測数30未満で除外した2件(field_id 5・2016年、580・2018年)の15行だけ。したがって、範囲の外のデータは DB にも無く、CSV の値(= DB の値)を使った。

## 処理が目的どおりか(記述用、`gc_check.csv`)

- **集団の中の開花日の範囲**(123件、28集団): 中央値6日、平均6.9日、最小0日、最大33日。0日の集団は7、7日以上の集団は13。窓の「何日目か」でそろえると、半数近くの集団で1週間以上ずれる。
- **同じ集団の圃場どうしの、窓内の1次差分の相関の平均**

| 入力 | 集団の平均 | ペアで重み付け | 集団ごとの最小〜最大 |
|---|---|---|---|
| 中心化の前(M_diff) | +0.315 | +0.219 | −0.155〜+0.896 |
| **GC_date** | **−0.032** | **−0.008** | −0.329〜+0.217 |
| GC_index | −0.319 | −0.227 | −1.000〜−0.090 |

- **GC_date で相関はほぼ0まで下がり、共通の降雨反応(の向きとタイミング)は取り除けている。**
- GC_index は負の相関になる。自分を含む平均を引くと、集団の大きさ n に応じて約 −1/(n−1) の負の相関が入るため(2件の集団は −1)。
- 図(`gc_examples.png`): 中心化の後も、雨の日に圃場ごとの山が残る。雨への反応の大きさが圃場(センサー)ごとに違うので、平均を引いても大きさの差は残る。

## モデル・分割・置換

段階13・14と同じ。
- M: MiniRocket(10000、乱数0〜9)→ StandardScaler(with_mean=False)→ RidgeClassifierCV(logspace(−3, 3, 10) × n_train)
- 分割は `make_splits(y, muniCd, 5, 20, 0)`、置換は市町村×年の中で1000回(置換 i の乱数は [0, i])。
- M_diff は段階13の median・M の結果をそのまま使った。

**確認(すべて True)**
1. GC_date の件数は123件で、段階13と同じ件・同じ並び(除外0)。
2. Pipeline と特徴量の使い回しが一致する(GC_date、乱数0、先頭10 fold)。
3. まとめて解いた置換20回分の帰無分布(全体・W・B)が、sklearn で1回ずつ学習した結果と一致する。
4. 置換5回分で分割が変わらない。
5. W・B・X をペア数で合わせると fold の AUC と一致し、fold の AUC・bacc が sklearn と一致する(全乱数)。
6. 手計算: 集団 15100_2017、圃場119、2017-08-19。ほかの7件の平均 0.383469、引いた値 −0.050981 が、スクリプトの値と一致した。
- そのほか、M_diff について、乱数0の先頭10 fold を計算し直して段階13の `folds.csv` と一致した。窓の生の値は段階13の X と一致した(差0)。

## 採用の判定

| 基準 | 結果 | 満たすか |
|---|---|---|
| 1. GC_date − M_diff の繰り返し平均の 2.5〜97.5%点が0より上 | [−0.130, −0.006] | **満たさない**(逆に負の側) |
| 2. GC_date の全体の AUC が帰無分布の95%点を上回る | 0.525 < 0.590 | **満たさない** |

- **GC_date は採用しない。主の入力は1次差分(M_diff)のまま変えない。**
- GC_date は M_diff より全体の AUC が0.08低い。差の区間は0を含まず、負の側にある(悪化を検出)。
- 仮説(W が上がる)も支持されない。W は 0.529 で M_diff(0.536)と変わらず、差の区間は [−0.141, +0.118] と広い。
- 下がったのは主に B(地域間、0.640 → 0.510)。共通の動きを引くと、地域間で当たっていた情報も一緒に消えた。
  - 段階14の A2 では、集団ごとに一律のずれは B に効かないことを確かめた。それでも B が消えたのは、M が集団をまたいで比べていたのが「集団に共通の動きに対して、その圃場がどう反応したか」という絶対的な形だったためと考えられる(推測)。中心化すると、隣の圃場との相対的な違いしか残らない。

## GC_index との比較から見た段階6の悪化の理由

- 「日付のずれ」で説明できるなら、同じデータで GC_date が GC_index より良くなるはず。**結果は逆で、GC_date(0.525)は GC_index(0.552)より低い。** 日付のずれは段階6の悪化の主な理由ではない。
- GC_index(段階6の方式)も、median の123件では 0.552 と M_diff より低い(差を検出)。段階6(0.448、label_muniyear の82件)ほどは下がらなかった。
  - この差は、ラベルと件数の違い(82件 → 123件)によるもので、そろえ方の違いでは説明できない。
  - 段階6の main には1件だけの集団が2つあり、その系列は全日0になっていた。
- まとめ: 集団内中心化は、そろえ方によらず、M の性能を下げる。段階6の悪化は、中心化そのもので地域間の情報が消えることが主な理由と考えられる。

## 結論

- 暦の日付でそろえた集団内中心化(GC_date)は、共通の降雨反応を取り除けた(1次差分の相関 +0.22 → −0.01)。しかし AUC は 0.607 → 0.525 に下がり(差を検出)、帰無分布の95%点にも届かない。**採用の基準を満たさないので、主の入力は1次差分のまま。**
- 地域内 W は上がらなかった(0.536 → 0.529)。「共通の動きを除けば地域内の違いが見える」という仮説は、このデータでは支持されない。
- 集団内中心化を試したのは、段階5・段階6・段階16の3回。3回とも悪い向きだった。

## 次の候補(ユーザーと相談する)

- 引き算ではなく、比や圃場ごとの尺度合わせで、雨への反応の大きさの差を扱う(図で中心化の後も山が残っていたため)。
- 中心化した系列を1次差分に「加える」(2チャンネル)。共通の動き(地域間の情報)を残したまま、隣との違いを足せるかを見る。ただし、試す回数が増えるので、判定を事前に固定して1回に限る。
