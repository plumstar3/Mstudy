## わかったこと
- sktime 1.2.0 の `Rocket` と `RocketClassifier` は、長さの揃わない系列を受け付けない。タグ `capability:unequal_length=True` は実装と合っていない。このため D-005 の前提が崩れ、「要再検討」にした
- 公式実装 `external/rocket` は、NumPy 2 で削除された `np.NINF` を使っているので import の時点で失敗する。`-np.inf` に直せば動く
- 論文の ROCKET は、長さの揃わないデータを長さのまま処理していない。UCR が配布する調整版(最長に合わせて低振幅ノイズでパディング)を使っている。カーネルは、入力が z 正規化されている前提で作られている
- ArrowHead での比較(10回): 基準 0.810(論文値 0.8143 とほぼ同じ)、最短に切り揃え 0.794、MiniRocketVariable 0.776、長さを変えず適用 0.731、ノイズパディング 0.671、補間 0.618。**時間軸の位置を保ったまま長さを揃える方法が最良**だった
- 長さを変えずに適用する方法は、学習データの最短長より短いテスト系列があるとゼロ除算になる。短い系列だけノイズでパディングすれば避けられる
- `rocket_demo.py` の 0.977 は非公式分割の値で、公式分割では 0.806
- 調査報告から得た候補: 積算 GDD(生育ステージの代わり)で揃える、1次差分を使う(センサーごとの水準差を消せる)、生育時期ごとの寄与を説明する(MIPV や ROCKET-LRP)。積算 GDD は `outputs/gdd/gdd_daily.csv` にあり、94件すべてそろっている
