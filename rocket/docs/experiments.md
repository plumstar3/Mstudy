## EXP-024: 品種が集団の中で同じ集団だけでの評価

- 日付: 2026-11-09
- スクリプト: `analysis/stage15/run_stage15.py`(`rocket\venv_rocket\Scripts\python rocket\analysis\stage15\run_stage15.py`、この PC・28並列で157秒)。試運転は `--n-seeds 1 --n-perm 20`。参考の集計に段階13の `outputs/stage13/oof_scores.csv`・`folds.csv` を使う
- 目的・仮説: EXP-023 の B3(品種 + 播種日)は偶然水準ではなく、M との差も検出できなかった。品種が集団の中で1つだけの集団に絞って学習から評価までをやり直し、M が「品種の違いが土壌水分の動きに表れたもの」を拾っている可能性を確かめる。この部分集合では品種は地域内のラベルの手がかりになりえない
- 経緯: **EXP-023 の結果を見てから追加した解析**。判定の基準(下の「判定」)は実行前に固定した

### 設定
| 項目 | 値 |
|---|---|
| データ | `data/processed/stage13/label_muniyear_median_*`(123件・28集団)から、集団の全件で `breed` が同じで欠測の無い集団だけ。**76件(多収40 / 低収36)、19集団、16市町村**(2016年53件、2017年16件、2018年7件) |
| 除いた集団 | 品種の欠測を含む5集団(2209_2017・23213_2016・32203_2016・32203_2017・8302_2017)、品種が2つの4集団(17210_2016・20202_2016・23212_2017・8201_2016)。計47件 |
| ラベル | `label_muniyear_median` |
| 系列の揃え方 | 開花起点 0〜+59 日 |
| 入力の形 | M: 1次差分。B1: VWC の要約統計。B3: 品種の one-hot + 播種日の通日(EXP-023 と同じ) |
| モデル | EXP-022 と同じ(M は乱数0〜9)。B1・B3 は LR(C=1) |
| CV | 部分集合で `make_splits(y, muniCd, 5, 20, 0)` を作り直した(テスト件 4〜33) |
| 置換検定 | 市町村×年の中で1000回(置換 i は [0, i])。分割は変わらない |
| 判定(事前に固定) | 主(1つ): 部分集合で学習し直した M の全体の AUC が帰無分布の95%点を上回るか。W・B・X、対ごとの差、B1・B3 は記述のみ |

- 段階14の報告の「20集団・80件前後」と数が違うのは、欠測を含む集団を除いたため。段階14の数え方は欠測を「不明」という1つの品種として数えていて、品種がすべて欠測の 2209_2017 を「品種が1つ」の集団に入れていた
- 部分集合のクラス構成: 同数12集団・56件、数が違う4集団・15件、片方だけ3集団・5件

開始時の確認(すべて True): 部分集合の定義どおり、Pipeline と特徴量の使い回しが一致、まとめて解いた帰無分布 = sklearn で1回ずつ学習した結果(置換20回)、置換5回で分割が変わらない、W・B・X をペア数で合わせると fold の AUC。

- 対ごとの差: M − B3 AUC +0.206(繰り返しの2.5〜97.5%点 [+0.094, +0.383]、差を検出)、M − B1 AUC +0.128([+0.038, +0.250]、差を検出)

### 考察
- 主の判定: 上回る。**品種が集団の中で同じ条件でも、土壌水分の時系列は多収・低収を分類できる(M の結果は品種では説明できない)**
- B3 はこの部分集合で偶然水準(0.575 → 0.472)まで下がった。EXP-023 で B3 が当たっていたのは、今回除いた集団から来ていたと考えられる

## EXP-012: alpha が上限に張り付く理由の観察

- 日付: 2026-10-28(別の PC で実行、92秒)
- スクリプト: `analysis/stage8/alpha_diag.py`(`rocket\venv_rocket\Scripts\python rocket\analysis\stage8\alpha_diag.py`)
- 目的: 段階6〜8 のすべての設定で RidgeClassifierCV が alpha の上限(1000 × n_train)を選んだ理由を見る。観察用で、評価の設定は変えない
- 詳細: `analysis/stage8/alpha_diag_report.md`

### 設定
| 項目 | 値 |
|---|---|
| 設定 | MR_diff、R0 / R1 / R2 × PPV のみ・PPV+max(特徴量は段階6〜8と同じ) |
| 分割・乱数 | 5分割 × 20回(段階6と同じ)、カーネルの乱数0、置換50回(市町村×年の中) |
| alpha の候補 | logspace(−3, 6, 19) × n_train。sklearn の GCV と同じ式で計算(cv_results_・1件ずつ抜いた学習と一致を確認) |

### 結果
| 設定 | GCV 最小が上端(10⁶) | df(上限 1000) | テスト AUC(alpha/n = 0.001 / 1000 / 10⁶) |
|---|---|---|---|
| MR_diff | 88% | 4.5 | 0.630 / 0.605 / 0.542 |
| R0_ppv | 49%(残りも主に 3162〜10⁴) | 3.1 | 0.507 / 0.542 / 0.541 |
| R1_ppv | 100% | 7.2 | 0.463 / 0.478 / 0.456 |
| R2_ppv | 100% | 5.1 | 0.499 / 0.489 / 0.483 |

- GCV は alpha とともにほぼ単調に下がり、切片だけのモデルの LOO 2乗誤差(1.031)に近づく。置換したラベルでも同じ。
- LOO 正解率・AUC は切片の学習し直しによる下向きの偏りで 0.5 を下回り、alpha → ∞ で AUC → 0(置換でも同じ)。
- MR_diff のテスト AUC は alpha が小さいほど高いが、置換の95%点も高くなる(0.633 vs 1000 で 0.599)。

### 考察
- 上限に張り付くのは、GCV が2乗誤差で選ぶため(信号が弱く、縮めるほど2乗誤差が下がる)。AUC は並び順だけを見るので、GCV の基準と主な指標がずれている。

## EXP-002: 長さの揃わない系列への対処法の比較(ArrowHead、10回)

- 日付: 2026-10-20
- スクリプト: `scripts/compare_unequal_handling.py`(`rocket\venv_rocket\Scripts\python rocket\scripts\compare_unequal_handling.py`)。共通部品は `src/rocket_kernels.py`
- 目的・仮説: 長さの揃わない系列への対処法(ユーザーの調査で挙がった4案)のうち、どれが ROCKET の精度を保てるかを比べる。論文 4.1.3 節では、長さの揃わないデータを最長に合わせて低振幅ノイズでパディングしている(UCR 2018 の調整版)
- EXP-001 から直した点: 全方法で系列を本来の長さで z 正規化した(論文 3.1 節の前提)。長さなどのパラメータは学習データだけから決めた。論文と同じく10回繰り返した

### 設定
| 項目 | 値 |
|---|---|
| データ | ArrowHead 公式分割(学習36 / テスト175、元の長さ251) |
| 不揃いにする方法 | 各系列を長さ L ~ U[100, 251] に先頭から切り詰める。繰り返しごとに乱数を変える |
| 変換 | 公式 ROCKET(`src/rocket_kernels.py`、num_kernels=10000)。④だけ sktime |
| 分類器 | StandardScaler(with_mean=False) → RidgeClassifierCV(alphas=logspace(-3,3,10)) |
| ノイズの振幅 | 標準偏差 1e-3(z 正規化後) |
| 繰り返し | 10回(シード 0〜9。切り詰める長さ・カーネル・ノイズを変える) |

### 結果(Accuracy、10回の平均 ± 標準偏差)
| 方法 | 内容 | Accuracy | 時間/回 |
|---|---|---|---|
| 基準 | 切り詰める前(長さ251) | **0.810 ± 0.011** | 0.4秒 |
| ① ノイズパディング | 学習データの最長(245〜251)に合わせ、末尾を低振幅ノイズで埋める | 0.671 ± 0.051 | 0.4秒 |
| ② 補間 | 学習データの長さの中央値(162〜207)に線形補間で伸縮 | 0.618 ± 0.067 | 0.3秒 |
| ③ 長さを変えず適用 | カーネルを学習データの最短長(100〜109)で作り、1系列ずつ適用 | 0.731 ± 0.052 | 3.7秒 |
| ④ MiniRocketVariable | sktime `MiniRocketMultivariateVariable` | 0.776 ± 0.051 | 0.4秒 |
| [参考] 最短に切り揃え | 学習データの最短長に合わせて末尾を切る | **0.794 ± 0.029** | 0.2秒 |

- 全結果: `outputs/compare_unequal_handling/results.csv`
- 基準の 0.810 ± 0.011 は、論文値 0.8143 ± 0.0094(`external/rocket/results/results_ucr.csv`)とほぼ一致する
- 10回中6回で、学習データの最短長より短い系列がテストデータに0〜10本あった。③と[参考]では、その系列だけ末尾をノイズでパディングして学習データの最短長に揃えた。こうしないと、③はゼロ除算で止まる(パディングなしのカーネルの出力長が0になるため)

### 考察
- **時間軸の位置が揃っているかどうかで差が出た**。ArrowHead は全系列の先頭が同じ位置から始まるので、末尾を切っても各時点の意味は変わらない。そのため、最短に切り揃える方法が基準に近い精度を保った(0.794)。補間は系列ごとに伸縮の倍率が違い、同じ位置でも意味が変わるので、一番低かった(0.618)
- ①ノイズパディングは、調査で指摘されたとおり特徴量が薄まって低下した(0.671)。短い系列では、PPV(正の値の割合)を計算する範囲の大半がノイズになる。論文の UCR 2018 データとは、長さの揃わなさの程度が違う可能性がある
- ③は元の長さの情報をすべて使えるが、dilation の上限が最短長で決まり、長い系列の大きな構造をとらえにくい(0.731)。計算時間も約9倍かかる
- ④ MiniRocketVariable(0.776)は ROCKET 以外では一番よかったが、「当面 ROCKET のみ」という方針(D-005)から外れる
- **VWC に当てはめる際の注意**:
  - ArrowHead では長さの違いをランダムに作ったので、収量のラベルとは関係がない。VWC では、長さの違いは観測期間の違い(開始の遅れなど)を表す
  - VWC の系列長は 32〜151 日で、最長と最短の比が約4.7倍ある。ArrowHead の約2.5倍より大きい。最短に揃えると 32 日しか残らず、情報が大きく減る
  - このため、そのまま「最短に揃える」のではなく、**播種日(dap)などの基準で時間軸を揃え、多くの圃場が観測されている共通区間を切り出す**のが自然。短い圃場を除外するか、③のように扱うかは、件数(94件)とのかね合いで決める
- 繰り返し10回でも、①〜④の標準偏差は 0.05 前後ある。差が 0.05 程度の比較は慎重に見る

### 次にやること
- 実データで、dap 基準の共通区間をいくつか試す(例: 圃場の何割が観測されている区間か)。区間の長さと、残る件数の関係を先に集計する
- 共通区間に切り出す方法(案 A)と、③(案 B)を実データの GroupKFold で比べる
