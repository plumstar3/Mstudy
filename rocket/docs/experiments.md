## EXP-008: 確認用の解析と、1次差分での揃え方の比較

- 日付: 2026-10-26
- スクリプト: `analysis/stage6/precheck.py`(事前確認)、`analysis/stage6/run_stage6.py`(本体)。本番は別の PC(i9-14900K、32スレッド)で `analysis/stage6/run_stage6_local.py`(置換検定の Ridge をまとめて解く高速版。元の方法と完全に一致することを確認済み)を使い、478秒
- 目的: (1) 事前に固定した1つの仮説(main・diff・MiniRocket が偶然水準と基準線を上回るか)を確かめる。(2) 揃え方の比較を1次差分でやり直す。(3) 探索的な解析
- EXP-007 から変えた点: alpha の候補を MiniRocket 原論文と同じ尺度にした(logspace(−3,3,10) × n_train。原論文の normalize=True と等価であることを確認)。カーネルの乱数を10通りにした。確認用の置換を1000回にした
- 詳細: `analysis/stage6/report.md`

### 設定
| 項目 | 値 |
|---|---|
| データ | `data/processed/stage4/`(main 82、main_common / dap_common 77、main_obs 60、main_no_kakogawa 76、main_no_irrigation 70、label_year 58) |
| ラベル | `label_muniyear`(F4 だけ `label_year`) |
| モデル | sktime 1.2.0 MiniRocket(num_kernels=10000、random_state=0〜9)→ StandardScaler(with_mean=False)→ RidgeClassifierCV(alphas=logspace(−3,3,10)×n_train) |
| CV | `src/evaluation.py`: StratifiedGroupKFold(groups=muniCd) 5分割×20回。統計量は乱数ごとの「20回の繰り返し平均」の10通りでの平均 |
| 置換検定 | 市町村×年内で並べ替え、置換 i は乱数間で共通。実験D 1000回、ほか200回 |

### 結果([ ] は置換検定の p、q95 は帰無分布の95%点)
| 設定 | 件数 | AUC(乱数の範囲) | q95 | bacc | q95 | 判定 |

| **D main diff(確認用)** | 82 | **0.605 [0.035]**(0.602〜0.607) | 0.595 | 0.544 [0.13] | 0.562 | **AUC で当たっている**(基準線 0.483) |
| E main_common diff | 77 | 0.541 [0.29] | 0.614 | 0.502 [0.42] | 0.569 | × |
| E dap_common diff | 77 | 0.486 [0.57] | 0.610 | 0.493 [0.49] | 0.562 | × |
| F1 raw+diff(探索的) | 82 | 0.555 [0.21] | 0.599 | 0.518 [0.31] | 0.563 | – |
| F2 groupcenter→diff(探索的) | 82 | 0.448 [0.67] | 0.550 | 0.480 [0.57] | 0.536 | – |

| F3 main_no_kakogawa(探索的) | 76 | 0.618 [0.030] | 0.603 | 0.541 [0.15] | 0.564 | 探索的に95%点を超えた |

- 実験E の差(main − dap、10通りの乱数で平均): AUC +0.055(繰り返し平均の差の 2.5〜97.5% [−0.017, +0.131]、正の割合85%)、bacc +0.009(55%)→ 差は検出できなかった。向きは10通りの乱数すべてで開花起点が上

- alpha は F4 以外で97〜100% の fold が上限(1000 × n_train)。原論文の尺度でも張り付きは残る

- 出力: `outputs/stage6/`

### 考察
- 事前に決めた確認用の基準(AUC)では、1次差分の VWC 系列に、地域×年の中で多収と低収を順位づける弱い情報がある。ただし95%点を超えた幅は +0.010 で、bacc では超えない
- 揃え方の優劣は、1次差分でも検出できなかった

- スクリプト: `analysis/stage5/run_stage5.py`(`rocket\venv_rocket\Scripts\python rocket\analysis\stage5\run_stage5.py --n-perm 200`、約12分)
- 目的: (1) 揃え方(開花起点 vs dap)、(2) 入力の形(raw / znorm / diff / groupcenter)、(3) 感度分析の部分集合で主設定の結果が変わらないか、を確かめる
- 詳細: `analysis/stage5/report.md`

### 設定
| 項目 | 値 |
|---|---|

| A MiniRocket dap_common raw | 77 | 0.473 [0.68] | 0.443 [0.79] | × |
| A ROCKET main_common raw | 77 | 0.561 [0.17] | 0.594 [0.15] | × |

- Ridge の alpha は 91〜100% の fold で上限の1000が選ばれた。候補の範囲が足りない可能性がある

## EXP-004: 揃え方の起点と窓の候補、開花日の推定

- 日付: 2026-10-23
- スクリプト: `analysis/stage3/run_stage3.py`(`rocket\venv_rocket\Scripts\python rocket\analysis\stage3\run_stage3.py`)。日長と開花日の推定は `src/phenology.py`
- 目的・仮説: 大豆の開花までの発育は日長の影響を受けるので、積算GDD では開花がそろいにくい。開花日を起点にした窓を新しい候補として、dap 起点・積算GDD 起点と、残存件数と窓の長さで比べる。ROCKET の性能を見る前に、起点と窓を決める
- 詳細: `analysis/stage3/report.md`

### 設定
| 項目 | 値 |
|---|---|
| データ | `label_muniyear` 付き94件(開花日の実測あり66件) |
| 開花日の推定 | (i) 開花 dap の平均、(ii) 播種日の通日で回帰、(iii) 積算GDD の閾値、(iv) 必要GDD = a + b × 日長(播種日の日長 / 平均日長)。日長は Forsythe et al. 1995 の CBM、p=0.8333° |
| 推定の評価 | 市町村の Leave-One-Group-Out(18グループ)、推定値は整数の日に丸める |
| 窓 | dap: 始まり 20/30/40/50 × 終わり 89/99/109/119/129。開花起点: 始まり −30/−20/−10/0 × 終わり +49/+59/+69/+79。GDD: dap50・dap99 の中央値(803/1436)を ±200/±100/0 ずらす |
| 覆う判定 | 観測開始 ≤ 窓の始まり かつ 観測終了 ≥ 窓の終わり(各軸で) |

### 結果
| 開花日の推定 | MAE | 誤差 SD | 最大 |
|---|---|---|---|
| (i) 平均 | 6.24 | 7.37 | 18 |
| (ii) 播種日の通日で回帰 | **4.38** | 5.73 | 13 |
| (iii) 積算GDD | 6.26 | 8.45 | 25 |
| (iv-a) GDD + 播種日の日長 | 6.36 | 8.25 | 23 |
| (iv-b) GDD + 平均日長 | 6.86 | 8.56 | 24 |

| 起点 | 推奨の窓(80件以上で最長) | 長さ | 件数(多/低) | 地域 | 釣り合い/崩れ/消失 |
|---|---|---|---|---|---|
| dap | 50–109 | 60日 | 81 (41/40) | 19 | 21/6/2 |
| 開花起点 | 0〜+59 | 60日 | 82 (41/41)、うち推定22 | 21 | 24/5/0 |
| 積算GDD | 803–1336 ℃日 | 約40日 | 81 (41/40) | 19 | 22/5/2 |

- 出力: `outputs/stage3/`(`windows_*.csv`, `flowering_cv_*.csv`, `flower_estimates_missing28.csv`, `heatmap_windows.png`, `vwc_examples_dap_vs_flower.png`)

### 考察
- 開花のばらつきは、dap 軸で SD 7.1日、GDD 軸で日数換算 8.0日。GDD に揃えても開花はそろわない
- 開花起点 0〜+59 は dap 50–109 と同じ長さで、地域と集団の釣り合いがより良く残る。ただし22件が推定開花日に頼り、加古川の件数は推定が±2日ずれるだけで2〜8件に変わる

## EXP-002: 長さの揃わない系列への対処法の比較(ArrowHead、10回)

- 日付: 2026-10-20
- スクリプト: `scripts/compare_unequal_handling.py`(`rocket\venv_rocket\Scripts\python rocket\scripts\compare_unequal_handling.py`)。共通部品は `src/rocket_kernels.py`
- 目的・仮説: 長さの揃わない系列への対処法(ユーザーの調査で挙がった4案)のうち、どれが ROCKET の精度を保てるかを比べる。論文 4.1.3 節では、長さの揃わないデータを最長に合わせて低振幅ノイズでパディングしている(UCR 2018 の調整版)
- EXP-001 から直した点: 全方法で系列を本来の長さで z 正規化した(論文 3.1 節の前提)。長さなどのパラメータは学習データだけから決めた。論文と同じく10回繰り返した

### 設定
| 項目 | 値 |
|---|---|
| データ | ArrowHead 公式分割(学習36 / テスト175、元の長さ251) |
| 不揃いにする方法 | 各系列を長さ L ~ U[100, 251] に先頭から切り詰める。繰り返しごとに乱数を変える |
| 変換 | 公式 ROCKET(`src/rocket_kernels.py`、num_kernels=10000)。④だけ sktime |
| 分類器 | StandardScaler(with_mean=False) → RidgeClassifierCV(alphas=logspace(-3,3,10)) |
| ノイズの振幅 | 標準偏差 1e-3(z 正規化後) |
| 繰り返し | 10回(シード 0〜9。切り詰める長さ・カーネル・ノイズを変える) |

### 結果(Accuracy、10回の平均 ± 標準偏差)
| 方法 | 内容 | Accuracy | 時間/回 |
|---|---|---|---|
| 基準 | 切り詰める前(長さ251) | **0.810 ± 0.011** | 0.4秒 |
| ① ノイズパディング | 学習データの最長(245〜251)に合わせ、末尾を低振幅ノイズで埋める | 0.671 ± 0.051 | 0.4秒 |
| ② 補間 | 学習データの長さの中央値(162〜207)に線形補間で伸縮 | 0.618 ± 0.067 | 0.3秒 |
| ③ 長さを変えず適用 | カーネルを学習データの最短長(100〜109)で作り、1系列ずつ適用 | 0.731 ± 0.052 | 3.7秒 |
| ④ MiniRocketVariable | sktime `MiniRocketMultivariateVariable` | 0.776 ± 0.051 | 0.4秒 |
| [参考] 最短に切り揃え | 学習データの最短長に合わせて末尾を切る | **0.794 ± 0.029** | 0.2秒 |

- 全結果: `outputs/compare_unequal_handling/results.csv`
- 基準の 0.810 ± 0.011 は、論文値 0.8143 ± 0.0094(`external/rocket/results/results_ucr.csv`)とほぼ一致する
- 10回中6回で、学習データの最短長より短い系列がテストデータに0〜10本あった。③と[参考]では、その系列だけ末尾をノイズでパディングして学習データの最短長に揃えた。こうしないと、③はゼロ除算で止まる(パディングなしのカーネルの出力長が0になるため)

### 考察
- **時間軸の位置が揃っているかどうかで差が出た**。ArrowHead は全系列の先頭が同じ位置から始まるので、末尾を切っても各時点の意味は変わらない。そのため、最短に切り揃える方法が基準に近い精度を保った(0.794)。補間は系列ごとに伸縮の倍率が違い、同じ位置でも意味が変わるので、一番低かった(0.618)
- ①ノイズパディングは、調査で指摘されたとおり特徴量が薄まって低下した(0.671)。短い系列では、PPV(正の値の割合)を計算する範囲の大半がノイズになる。論文の UCR 2018 データとは、長さの揃わなさの程度が違う可能性がある
- ③は元の長さの情報をすべて使えるが、dilation の上限が最短長で決まり、長い系列の大きな構造をとらえにくい(0.731)。計算時間も約9倍かかる
- ④ MiniRocketVariable(0.776)は ROCKET 以外では一番よかったが、「当面 ROCKET のみ」という方針(D-005)から外れる
- **VWC に当てはめる際の注意**:
  - ArrowHead では長さの違いをランダムに作ったので、収量のラベルとは関係がない。VWC では、長さの違いは観測期間の違い(開始の遅れなど)を表す
  - VWC の系列長は 32〜151 日で、最長と最短の比が約4.7倍ある。ArrowHead の約2.5倍より大きい。最短に揃えると 32 日しか残らず、情報が大きく減る
  - このため、そのまま「最短に揃える」のではなく、**播種日(dap)などの基準で時間軸を揃え、多くの圃場が観測されている共通区間を切り出す**のが自然。短い圃場を除外するか、③のように扱うかは、件数(94件)とのかね合いで決める
- 繰り返し10回でも、①〜④の標準偏差は 0.05 前後ある。差が 0.05 程度の比較は慎重に見る

## EXP-001: 長さの揃わない系列を入力できるか(ArrowHead を切り詰め)

- 日付: 2026-10-20
- スクリプト: `scripts/check_unequal_length.py`(`rocket\venv_rocket\Scripts\python rocket\scripts\check_unequal_length.py`)
- 目的・仮説: VWC の系列長は 32〜151 日で揃っていない。どの実装なら、長さの揃わない系列をそのまま入力できるかを確かめる(D-005 の見直し)

### 設定
| 項目 | 値 |
|---|---|
| データ | ArrowHead 公式分割(学習36 / テスト175、元の長さはすべて251) |
| 不揃いにする方法 | 各系列を長さ L ~ U[100, 251] に先頭から切り詰める(結果: 最小101 / 中央176 / 最大251) |
| モデル | 各変換器(num_kernels=10000) → StandardScaler(with_mean=False) → RidgeClassifierCV(alphas=logspace(-3,3,10)) |
| 乱数シード | 42 |

### 結果
| 方法 | 入力形式 | 結果 |
|---|---|---|
| [基準] Rocket(長さを揃えたまま) | nested_univ | **0.806**(論文値 0.8143 とほぼ同じ) |
| 1. RocketClassifier | nested_univ | 失敗: 不揃いな長さに対応しない、と明示的にエラー |
| 2. Rocket 変換器 | nested_univ | 失敗: `all input arrays must have the same shape` |
| 2. Rocket 変換器 | pd-multiindex | 失敗: `cannot reshape array of size 6418 into shape (36,248,1)` |
| 2. Rocket 変換器 | df-list | 失敗: `elements of obj must have same length` |
| 3. MiniRocketMultivariateVariable | nested_univ | 0.646 |
| 4a. 公式 `rocket_functions` を import | - | 失敗: `np.NINF` が NumPy 2.0 で削除されている |
| 4b. 公式実装(`np.NINF`→`-np.inf`)を1系列ずつ適用 | 配列のリスト | 0.571(dilation の上限は最短の長さ101で決めた) |
| 5. 全系列を最短の長さ101に切り揃えて Rocket | nested_univ | **0.857** |

### 考察
- sktime 1.2.0 の `Rocket` と `RocketClassifier` は、どの入力形式でも長さの揃わない系列を受け付けない。タグ `capability:unequal_length=True` は実装と合っていない
- 長さの揃わない系列のまま動くのは、MiniRocketMultivariateVariable(3)と、公式実装を1系列ずつ適用する方法(4b)だけ。公式実装は `np.NINF` を `-np.inf` に置き換えれば NumPy 2 でも動く
- 精度は、長さを揃える方法(5: 0.857)が、揃えない方法(3: 0.646、4b: 0.571)より高かった。ただし、この設定では切り詰める位置が系列ごとにランダムで、ラベルと関係のない長さの違いが特徴量に入る。そのため、揃えない方法に不利な人工的な条件である。VWC では長さの違いが観測期間の違いを表すので、この結果をそのまま当てはめることはできない
- 公式分割での基準 0.806 は論文値を再現できている。EXP-000 の 0.977 は学習データが多い(168本)非公式分割の値なので、論文値とは比べられない
- いずれもシード1つ、1回だけの結果
