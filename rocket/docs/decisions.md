## D-001: 結合キーは `(field_id, year)`

- 日付: 2026-10
- 状態: 有効
- 決定: `Questionaire` と `SolidMoisture` を `(field_id, year)` で結合する。`muniCd` は `field_id` だけで結合する
- 理由: 収量と土壌水分は同じ圃場でも年ごとに値が違う。`muniCd` は圃場ごとに1つしかない
- 影響: `field_id` が NULL の行は結合できないので除外する(`Questionaire` は702行中611行が使える)

## D-003: 主ラベルは地域×年内の上下1/3 (`label_muniyear`)

- 日付: 2026-10
- 状態: 一部変更(主ラベルの部分は D-006 で `label_muniyear_median` に置き換え、2026-11-08)
- 決定: 同じ `muniCd`×年の中で収量の上位・下位を k = round(n/3) 件ずつ取り、1(多収)・0(低収)とする。4圃場以上のグループだけに付ける(94件)。同じ年の中だけで付ける `label_year`(202件)は比較用
- 理由: 地域による収量差を除き、土壌水分の効果だけを見るため。地域×年グループ106個の大半は2圃場以下なので、最小サイズを4にした
- 検討した他の案: 最小サイズを3以下にする → グループ内の順位の意味が薄れる
- 影響: 2つのラベルで同じモデルの精度を比べ、地域差を拾っていないか確かめる

## D-004: CV は `muniCd` 単位の GroupKFold

- 日付: 2026-10
- 状態: 有効
- 決定: `GroupKFold(groups=muniCd)` を使う。ランダム分割は使わない
- 理由: 同じ地域の圃場は気象や土壌が似ている。学習と検証に分けると情報が漏れ、精度が過大になる
- 影響: `label_muniyear` が付く地域は21で、1地域あたり2〜10件。fold 数は少なくなる

## D-005: 手法は当面 ROCKET のみ。`Rocket` 変換器 + Ridge で組む

- 日付: 2026-10(2026-10-23 に系列の揃え方を決定)
- 状態: **決定**(下の「決定(2026-10-23)」を参照)
- 決定: `Rocket` → `StandardScaler(with_mean=False)` → `RidgeClassifierCV(alphas=np.logspace(-3, 3, 10))`
- 理由: 系列長が32〜151日と揃っていない。sktime 1.2.0 の `RocketClassifier` は不揃いな長さに対応しないが、`Rocket` 変換器は対応する。この構成は `RocketClassifier` のデフォルトの内部構成と同じ
- 検討した他の案: MiniRocket / MultiRocket → 当面は ROCKET 単体で基準を作る
- **問題(2026-10-20 に判明)**: sktime 1.2.0 の `Rocket` は `capability:unequal_length=True` のタグを持つが、長さ32・100・151の系列を `pd-multiindex` で渡すと `ValueError: cannot reshape array of size 283 into shape (3,151,1)` になる。venv_rocket(pandas 3.0)と anaconda(pandas 2.2)の両方で同じ結果。長さの不揃いを扱えたのは `MiniRocketMultivariateVariable` だけだった。「理由」に書いた前提が成り立たないので、次の案から選び直す
  - A. 系列を揃えて固定長にする(共通の dap 区間で切り出す、補間・パディングなど)。未決定事項1「系列の揃え方」と一緒に決められる
  - B. 公式実装 `external/rocket/code/rocket_functions.py` のカーネルを、系列ごとに長さのまま適用する(ROCKET の論文上は長さが違っても扱える)
  - C. `MiniRocketMultivariateVariable` を使う(ROCKET のみという方針から外れる)
- **EXP-001 での確認(2026-10-20)**: ArrowHead を不揃いな長さにして試した。sktime の `Rocket` と `RocketClassifier` は、どの入力形式(nested_univ / pd-multiindex / df-list)でも失敗した。案 B は公式実装の `np.NINF` を `-np.inf` に直せば動き、案 C も動いた。案 A に当たる「最短の長さに切り揃える」方法の精度が一番高かったが、比較の条件が人工的なので、実データで比べてから選ぶ。論文の 4.1 節では、長さの揃わないデータセットを最長の長さまで小さな乱数でパディングして評価している
- **EXP-002 での比較(2026-10-20)**: ArrowHead で10回ずつ比べた。基準 0.810 に対し、最短に切り揃え 0.794、MiniRocketVariable(案 C)0.776、長さを変えず適用(案 B)0.731、ノイズパディング 0.671、補間 0.618 だった。時間軸の位置を揃えたまま長さを合わせる方法が一番よい。VWC では、dap 基準で共通区間を切り出す方法(案 A)が有力。ただし最短長の32日に揃えると情報が減りすぎるので、区間の取り方と残る件数を実データで確かめてから決める
- **決定(2026-10-23)**: 案A(系列を揃えて固定長にする)を採る。揃え方は次のとおり
  - 主設定: **開花起点(開花日 = 0日目)の 0〜+59 日、60点**。82件・21地域。開花日は実測を優先し、無い28件は段階3の (ii)「開花 dap = 97.70 − 0.2889 × 播種日の通日」(実測66件で学習)で推定する
  - 比較: dap 50–109、60点。81件
  - 感度分析: 実測開花日の件だけ(60件)/ 加古川(28210)を除く(76件)
  - 対象外: 開花前の期間を含む窓、開花の後に観測が始まる10件(と観測が窓の終わりより前に終わる2件)
  - 理由: 開花のばらつきは dap 軸で SD 7.1日、GDD 軸で日数換算 8.0日で、GDD に揃えても開花はそろわない(EXP-004)。80件以上残る窓では、開花起点 0〜+59 と dap 50–109 がどちらも60日で最長。開花起点は全21地域が残り、市町村×年の集団の釣り合いも最も良い(24集団。dap は21)。1日刻みで見ても開花起点の上限は83件で、開花前に広げると推定開花日の件(加古川)から落ちる(EXP-005)
  - 影響: 入力は `src/windows.py` で作り、`data/processed/stage4/` に保存した(EXP-006)

## D-006: 主ラベルを `label_muniyear_median` に変える

- 日付: 2026-11-08
- 状態: 有効(D-003 の主ラベルの部分を置き換える。D-003 は「一部変更」)
- 決定: 主ラベルを `label_muniyear_median`(市町村×年の中の中央値分割、4圃場以上の集団)にする。`label_muniyear` は感度分析として残す
- 理由:
  - 地域と年の影響を除ける(各集団で多収と低収が同数)性質は、`label_muniyear` と同じ
  - `label_muniyear` の件はすべて同じラベルで median に含まれる(上位1/3 ⊂ 上位1/2。94件すべてで確認)
  - 窓0〜+59日で使える件数は77件から123件に、地域内のペアは62組から147組に増える
  - 2〜3圃場の集団を含めないので、min2 のような小さな集団のラベルのノイズが入らない(EXP-022)
  - 入力は土壌水分だけに固定する。品種・播種日は入力に入れず、交絡の確認用の基準線(B3)として使う
- 注意:
  - 複数のラベルを試した後での選択なので、結果が良かったことは理由にしない。これ以降の確認用の解析は、判定を事前に固定して行う
  - 段階14(EXP-023)では、品種+播種日だけの基準線 B3 が AUC 0.575(p=0.047)で、品種との交絡を否定できなかった。段階15(EXP-024)で、品種が集団の中で同じ部分集合(19集団・76件)で学習し直したところ、M は AUC 0.678(p=0.011)で当たり、B3 は偶然水準(0.472)だった
- 検討した他の案:
  - `label_muniyear_median_min2`: 件数は最多だが、ラベルのノイズが大きい(段階13で偶然水準)
  - `label_year` 系: 地域差と交絡する
  - 都道府県×年の中のラベル: 市町村の差がラベルに入る(84集団中35集団が片方のクラスだけ)
- 影響: 主の結果は段階13(EXP-022)の median の全123件(M の AUC 0.607、p=0.026)。入力は `data/processed/stage13/label_muniyear_median_*`

## D-007: 今後の判定は全体 AUC で行う。地域内 W・地域間 B は記述として出す

- 日付: 2026-11-17
- 状態: 有効(ユーザーの決定)
- 決定: 段階29以降、事前に固定する判定は全体 AUC(fold の AUC の平均)で行う。地域内 W(同じ市町村×年のペア)と地域間 B(同じ年・違う市町村のペア)は、これまでどおり計算して記述として出す。結論は「全体として見分けられる」の形で書き、地域内の判別とは区別する
- 理由: 地域内 W のペアは主ラベル(123件)で141〜147組しかなく、帰無分布の SD から求めた検出力80%に必要な W は 0.665〜0.693(EXP-037)。N の W は3つの設定で 0.613〜0.616 と安定していたが、どれも95%点に届かなかった。今の件数では、W を判定に使っても検出できない
- 検討した他の案: W を判定に使い続ける(検出できない検定を繰り返すことになる)/ 2〜3圃場の集団を加えて W のペアを増やす(ラベルのノイズが大きい、EXP-022 の min2)
- 影響: 段階29(EXP-038)から適用する。段階28以前の W を判定に使った結論(EXP-021・022・028〜030・037 など)は変えない

## D-009: 今後は日単位のデータで進め、1時間の系列をそのまま入力にはしない

- 日付: 2026-11-24
- 状態: 有効(ユーザーの決定)
- 決定: これから作る入力は日単位の土壌水分データ(`大豆元データ/soilmoisture_daily_v2.csv`)から作る。1時間の系列(`soilmoisture_hourly_v2.csv`)を1440点のまま MiniRocket の入力にするのはやめる
- 理由(段階31、EXP-040。主ラベル119件、同じ件・同じ分割で比較):
  - 1時間の入力(生の値・1次差分・減る方向・雨の直後の減少・無降雨日の減少)は、どの形も全体 AUC が偶然の水準を上回らなかった(最高 H_Npost 0.572、p = 0.104、Holm 後 0.52)
  - 同じ件数の日平均では、雨の直後の減少 Dy_Npost が Holm 補正の後も上回った(0.658、p = 0.010、Holm 後 0.0498)
  - 同じ形どうしでは1時間のほうが約0.09〜0.10低い向きだった(1次差分 −0.093、減る方向 −0.098、雨の直後の減少 −0.086。Holm 補正の後は差を検出できない)
  - 1時間の1次差分 H_D では、Ridge の alpha が99%の fold で上限に張り付いた(日平均の Dy_D は82%)
  - **「1時間データに情報が無い」とは言えない。** 確かめたのは「MiniRocket(10000)に1440点をそのまま入れる形では、日平均より悪かった」ということだけで、dilation の範囲・特徴量の配分・平滑化・間引きは変えていない
- 検討した他の案:
  - 1時間の系列のまま、MiniRocket の設定(dilation、特徴量の配分)を変えて続ける → 日平均で結果が出ている形があり、件数が少ない中で設定の探索を増やすことになる
  - 1時間データを数時間ごとに平均し直して入力にする → 次のステップの候補として残す(下の「影響」)
- 影響:
  - 段階32以降の入力は日単位で作る。1時間データは捨てずに残す
  - **1時間データから日単位の特徴を作る使い方は、次のステップの候補として残す**(例: 1日ごとの夜間の減少量で、排水に近い指標。段階31の探索では、雨の直後の夜の減少 H_Npost_night が 0.574、昼 0.532 で、差は検出できなかった)

## D-010: 日平均は24時間そろう日だけを使う(n_hours のしきい値)

- 日付: 2026-11-24
- 状態: **廃止(→ D-013、2026-11-24)**。旧の日単位データ(fixed 版)には n_hours が無く、当てはまらない。もとは有効(ユーザーの決定)
- 決定: `soilmoisture_daily_v2.csv` の日平均は、`n_hours = 24`(その日の24時間すべてに値がある)の日だけを使う。窓(開花起点 0〜+59 日)の中に24時間そろわない日がある件は除く。主ラベル `label_muniyear_median` では **119件(多収60/低収59)**
- 理由:

## D-016: 段階36(選択込みの置換検定、max-T)の事前登録

- 日付: 2026-11-25
- 状態: 有効(2026-11-25 にユーザーが承認。計算を始める前に記録)
- 目的: 分類器を使わずに土壌水分の動態と収量の関連を検定する。段階32〜35では検定の種類・パラメータを変えた試行が累計456個(補正前 p < 0.05 は38個、Holm 後0個)。今回は (1)「複数の組を試して最良を選ぶ」手順全体を置換の中で毎回やり直し、最良を選んでも有効な p(選択込みの p)を出す、(2) 目的変数に連続値の相対収量を使い、特徴量を雨のイベントに揃えて検出力を上げる
- データ: `soilmoisture_timeseries_fixed.csv`(D-013)、515 を除く。窓は flower_date を0日目とした 0〜+59 日、収穫日より後は使わず、60日そろう件だけ(段階34と同じ規則)。Δθ(t) = θ(t) − θ(t−1)、t = 1〜59。0日目の Δθ は開花日の前日の観測から作り、雨の日の判定にだけ使う(前日が無ければ雨の日なし)
- 層: 市町村×年。`label_muniyear_median` が付く集団(4圃場以上)に限る
- 目的変数:
  - (Y1) 相対収量 y_rel = log(収量 / 市町村×年の平均)。平均は段階19と同じく、その集団の全件(窓の外の件も含む、`field_year_labeled.csv`)で取る。上の集団で60日そろう**全件 123件・27集団**(主ラベルの120件 + 中央の空欄3件)。年ごと 2016 81 / 2017 34 / 2018 8件。集団の大きさは2件が2集団、3件が1集団、4件以上が24集団
  - (Y2) `label_muniyear_median`(120件)。段階32〜34との比較用
- 雨の日の定義(窓の0〜59日目の Δθ で判定。開花日より前の雨は見ない):
  - θ0(主): Δθ > 0(段階29の主)
  - θ2: Δθ ≥ 0.002(段階29の記述用と同じ)
  - θ5: Δθ ≥ 0.005
  - 雨のイベント = 雨の日が続く区間(最後の雨の日 e で代表する)。どの定義でも全件でイベントは1件以上ある(最小 6 / 5 / 4 件)
  - **APCPRA による定義は見送る**(ユーザーの決定)。理由: 段階29の照合(`outputs/stage29/check_rain_vs_apcpra.csv`)で、VWC で雨の日でない日の56%が APCPRA ≥ 1 mm(当日か前日)であり、使うには新しいしきい値を後から決める必要がある
- 特徴量(圃場ごとのスカラー。減少は負の値のまま。値が小さいほど大きく減る):
  - F1 N_post(k = 1, 2, 3, 5): イベントごとに、e の翌日から k 日(e+1 … e+k)の min(Δθ, 0) の平均。次の雨の日の前と窓の終わり(59日目)で打ち切る。打ち切りで後の日が無いイベント(e = 59)は使わない。イベントの値を圃場の中で平均する
  - F2 減少率: イベントごとに、F1(k = 3)の値 ÷ 上昇量。上昇量 = θ(e) − θ(s − 1)(s はその区間の最初の雨の日。s = 0 なら開花日の前日の θ)。上昇量が 0.002 未満(段階32の AMP_MIN)のイベントは使わない。圃場の中で平均する。使えるイベントが無い圃場は NaN として、その組の計算から除く
  - F3 N_dry: t = 1〜59 のうち、雨の日でもなく、雨の日の後3日以内でもない日の min(Δθ, 0) の平均。該当日が無ければ NaN
  - F5 イベント数: 窓の中の雨の日の区間の数
  - F4 N: t = 1〜59 の min(Δθ, 0) の平均(雨の定義を使わない)
  - F6 P(対照): t = 1〜59 の max(Δθ, 0) の平均。**max の族には入れず**、別に報告する
  - 特徴量は 3定義 × {F1 ×4、F2、F3、F5} + F4 = **22個**(+ 対照 P)
- 統計量(すべて層の中だけで比べる。向きは両側):
  - S1(Y1): 層ごとに特徴量と y_rel の Spearman ρ を計算し、層の件数で重み付けして平均する。**3件以上の層だけ**(2件の層は ρ が必ず ±1 になるため)。層の中で特徴量か y_rel が全部同点なら、その層は除く
  - S2(Y1): 層ごとに**正規化した順位 u = (rank − 0.5) / n**(n はその層の件数、同点は平均順位)を特徴量と y_rel の両方に作り、全件で u どうしの Pearson 相関を取る。層の大きさで順位の幅が変わり、大きな層が重く効くのを避けるため(ユーザーの指示)。全件の層を使う
  - S3(Y2): 層内 AUC(同じ層の中の多収・低収のペアだけで数える。同点は0.5)
- 族と組の数:
  - **Y1 の族: 22特徴量 × {S1, S2} = 44組(主の判定)**
  - Y2 の族: 22特徴量 × S3 = 22組
  - 対照 P: S1・S2・S3 の3組(族の外)
  - 合計69組
- 手順:
  1. 実データで全組の統計量を計算する
  2. 層内置換を10,000回(置換 i は `default_rng([0, i])`)。圃場と(y_rel、ラベル)の対応を、層の中で同時に並べ替える。中央の空欄3件もラベルの並べ替えに入る(各層のラベルの数は保たれる)
  3. 各組の統計量を、置換の帰無分布(10,000回)の平均と標準偏差で z にする。実データの |z| と、置換の各回の族内の最大 |z| を記録する
  4. 選択込みの p = (#{置換の族内最大 |z| ≥ 実データの |z|} + 1) / (B + 1)(Westfall–Young の single-step max-T。強い FWER の制御)
  5. 参考: 各組の補正前の両側 p = (#{置換の |z| ≥ 実データの |z|} + 1) / (B + 1) と、族内の Holm 後 p
- **判定(主): Y1 の族で選択込みの p < 0.05 の組があれば「少なくとも1つの組で関連あり」とする**。Y2 の族は比較用(同じ方法で選択込みの p を出す)
- 記述用:
  - specification curve: 全組の z を並べた図(並べ替えた z と、組の内容を示す下段の表)。対照 P も別の色で入れる
  - 最良の組(Y1・Y2 の族でそれぞれ |z| が最大の組)の年ごとの層内の向き(2016 / 2017 / 2018)。**年ごとの件数を添え、2018年(8件)は記述のみとし解釈しない**(ユーザーの指示)
  - 最良の組の効果量: 層内 Spearman ρ(S1)と、市町村単位のブートストラップ(2000回)による95%区間
  - 同じ向き(正 / 負)の組の割合。**組どうしの相関が強い(同じ特徴量の雨の定義違い、S1 と S2)ため独立な証拠の数ではない**と注記する(ユーザーの指示)
- 試運転: 置換100回はコードの確認と所要時間の見積もりだけに使う。p は run_log にだけ残し、レポートに載せず、結果を見て組や設定を変えない(D-011 と同じ扱い)
- レポートに必ず入れる注意: 特徴量の候補(N_post など)は段階29で同じデータから見つけた仮説で、double dipping の問題は残る。選択込みの p は今回の69組の中での選択だけを補正し、段階26〜35の探索は補正していない。有意差が無くても関連が無い証拠ではない(検出力不足の可能性、D-007)
- 影響: `analysis/stage36/run_stage36.py`(新規。段階32の `permute_within`・`holm` を import して使い、既存のファイルは変更しない)、入力 `data/processed/stage36/`、出力 `outputs/stage36/`

## D-018: 段階38(尺度合わせした N_post 入力の比較)の設定

- 状態: 有効(計算を始める前に記録。本研究は探索的な解析として進める、2026-11-28 のユーザーの決定)
- 目的: 段階29・31で全体 AUC が置換の95%点を上回った雨の直後の減少 N_post の識別力が、「雨の後の排水の速さ」から来ているのか、「雨に対するセンサー・土壌の反応の大きさ」から来ているのかを切り分ける。段階36で N_post は上昇量 P と強く逆相関した(Spearman −0.79〜−0.92)
- データ: `soilmoisture_timeseries_fixed.csv`(D-013)、515 を除く。窓は flower_date を0日目とした 0〜+59 日、収穫日より後は使わず60日そろう件(段階36の `data/processed/stage36/theta.npy`・`meta.csv` を使う)。主ラベル `label_muniyear_median`(120件)
- 土壌物性(`data/processed/stage38/soil_physical.csv`、元Excel は読むだけ):
  - 2016・2017「収量土壌分析」、2018「2018土壌分析」。サンプル名を `大豆元データ/questionaire_place.csv` の (year, place) で field_id に対応づける(3年とも表記は一致、2018年は A01 形式)
  - 列(0始まり): 仮比重 bd 2016 44〜46 / 2017 47〜50 / 2018 17、θ30 2016 47〜49 / 2017 51〜54 / 2018 19、θ5 2016 50〜51 / 2017 55〜58 / 2018 21、作土深 2016 63 / 2017 79 / 2018 29、土粒子密度 2017 38 / 2018 34(真比重)
  - 複数の列は、実施要領の「深さ5〜10cm部からコア2個採取」から**反復(圃場内のコア)**と判断し、数値がある列の平均を使う。数値でない記入(「測定せず」「－」など)は欠測
  - 2016年 G1〜G12(20202_2016)は θ30・θ5 の列に三相分布(気相・液相・固相)が入っているので、θ30・θ5 は欠測とする
  - 2018年の18列は G01〜G10 では pF1.5 試料の仮比重(41列と同じ値)で反復ではないため、仮比重は17列だけを使う(G06・G07 は欠測)
  - 2018年 I01・I07 のように θ が 1.5 未満の値は、すでに割合で書かれているとみなして100で割らない
  - % は100で割る。φ = 1 − bd / 2.6(真比重は2.6に固定)、粗孔隙量 a30 = φ − θ30
- 入力(長さ59の1チャンネル、t = 1〜59):
  - 雨の日と雨の直後の定義は段階29の `components` と同じ: 雨の日 Δθ > 0(θ0)、k = 3、雨の直後 = 直前3日以内に雨の日があり、その日は雨の日でない。窓の最初の日の判定には開花日より前の Δθ(t = −2〜0)を使い、観測が無い日は雨の日なし。θ(−1) は `theta.npy`、θ(−3)・θ(−2) は fixed 版から読む
  - **NP(基準)**: 雨の直後の日は min(Δθ, 0)、ほかの日は0
  - **NP_rise**: NP の各値を、その日が属する雨のイベント(直前の雨の日の連続区間 s〜e)の上昇量 θ(e) − θ(s−1) で割る。イベントは t = −2〜59 の雨の日で作る(s の最小は −2)。上昇量 < 0.002 または計算できないイベントの後の値は0にし、件数・日数を記録する
  - **NP_fc**: NP ÷ θ30(圃場ごとの定数)
  - **NP_phi**: NP ÷ φ(同上)
  - 参考(記述のみ): P 系列 max(Δθ, 0)
- 解析集合:
  - **主: 120件のうち bd と θ30 の両方がある件(見込み108件、多収54/低収54、25集団・20市町村)**。主の4入力と4基準線を同じ件・同じ分割で比べる
  - 参考(記述): 120件全体の NP、bd がある件(見込み118件)での NP_phi。それぞれの件で分割を作り直す
- 分類器(段階29と同じ): sktime 1.2.0 の MiniRocket(10,000、カーネルの乱数 0〜9)→ StandardScaler(with_mean=False)→ RidgeClassifierCV(alphas = logspace(−3, 3, 10) × n_train)。分割は `make_splits(y, muniCd, 5, 20, 0)`
- 基準線: StandardScaler → LogisticRegression(L2、C = 1)。説明変数は bd のみ / θ30 のみ / a30 のみ / bd + θ30 の4通り。同じ分割
- 置換検定: 市町村×年の中でラベルを並べ替える(置換 i は `default_rng([0, i])`、分割は固定)。MiniRocket の入力は各200回(帰無分布は乱数10通りの平均、段階27・29と同じ)、基準線は各1000回。p = (1 + #{帰無 ≥ 観測}) / (1 + 回数)。**主の4入力(NP・NP_rise・NP_fc・NP_phi)の全体 AUC の p に Holm 補正をかけて併記する**。参考の入力も同じ置換200回で95%点と p を出す(記述)
- 差: 尺度合わせ版 − NP(3つ)と、各入力 − 最良の基準線(全体 AUC が最も高い基準線。結果を見て選ぶので記述)の全体 AUC の差を、市町村単位のクラスターブートストラップ2000回で95%区間にする(段階27・29の `pair_sums`・`boot_diff`)。基準線のスコアは乱数によらないので、10通り分を同じ値で並べて重みをそろえる
- 記録: alpha が上限に張り付いた割合(入力ごと)、各物性の件数(年別)、物理的に矛盾する件(φ < θ30 など)、層(市町村×年)内の分散の割合、同じ (year, place) の重複、件数が減って多収・低収の釣り合いが崩れる層、尺度合わせ前後の圃場ごとの要約(NP・上昇量・NP_rise・NP_fc・NP_phi の圃場ごとのイベント平均、P の平均、物性)の Spearman 相関
- 読み方(判定は全体 AUC、D-007。W・B は出さない):
  - 尺度合わせ版(特に NP_fc・NP_phi)の AUC が95%点を上回り、NP との差の区間が0を含む → 反応の大きさを土の物性でならしても情報が残る。排水の速さに情報がある、という解釈を支持する
  - 尺度合わせ版の AUC が偶然の水準に下がり、NP との差の区間が0より下 → N_post の識別力は反応の大きさ(土・センサーの設置条件の違い)によるものが大きい
  - NP_rise だけが下がり、NP_fc・NP_phi は残る → データから作る尺度合わせ(上昇量)と土の物性による尺度合わせは別のものを見ている、と記述する
  - 基準線(土の物性だけ)が95%点を上回る → 尺度合わせ版の AUC の一部が土の情報そのものから来ている可能性を書き、尺度合わせ版 − 基準線の差も見る
  - n ≈ 108 では入力どうしの差が0.05程度でも区間が0を含みやすい。「差がない」とは書かず「差は検出できなかった」と書く
- 試運転(`--part trial`、乱数2通り・置換20回・ブートストラップ100回、`outputs/stage38/trial/`)はコードの確認と所要時間の見積もりだけに使い、その結果を見て設定を変えない
- 注意: N_post は段階29で同じデータから見つけた仮説で、double dipping の問題は残る。物性の測定は播種後・中耕培土前の作土中央(深さ5〜10cm)のコアで、センサー(スキ床の約3cm上)と深さが違う
- 影響: `analysis/stage38/run_stage38.py`(新規。段階6・12・13・27の関数を import して使い、既存のファイルは変更しない)、`data/processed/stage38/`、`outputs/stage38/`。Excel を読むため venv_rocket に openpyxl(と資料確認用の python-docx・python-pptx)を追加し、`requirements.txt` を更新した

## D-019: 段階39(割り算を使わない N_post の切り分け)の設定

- 日付: 2026-11-28
- 状態: 有効(計算を始める前に記録。段階38の結果を見た後に決めた設定なので探索的な解析として扱う)
- 目的: 段階38で上昇量で割った NP_rise は偶然の水準(0.490)に下がったが、小さな上昇量のイベントの後で値が極端になり(< −1 が296個)、ノイズによる低下と区別できなかった。割り算に頼らずに、N_post の識別力が雨での上昇量(反応の大きさ)の情報と同じものか、別の減り方の情報を含むかを切り分ける
- データ: fixed 版(D-013)、515 を除く、開花起点 0〜+59 日。段階36の `theta.npy`・`meta.csv` と、段階38の `theta_ext`(θ(−3)〜θ(59))を使う。主ラベル `label_muniyear_median`
- 定義(段階38と同じ): 雨の日 Δθ > 0(t = −2〜59 で判定、開花日より前の観測が無い日は雨の日なし)、イベント = 連続する雨の日 s〜e、上昇量 r = θ(e) − θ(s−1)、雨の直後 = e の翌日から k = 3 日(次の雨で打ち切り、窓の中 t ≥ 1 だけ)、j = t − e(1〜3)。段階38の関数(`load_cases`・`theta_ext`・`s29_runs`)を import し、イベントへの日の割り当ては段階38の `build_inputs` と同じ規則で行い、段階38の `rain_events.csv`・`NP_X.npy` と一致することを確認する
- 入力(長さ59の1チャンネル、t = 1〜59):
  - **NP(基準)**: 雨の直後の日は d = min(Δθ, 0)、ほかの日は0(段階38と同じ)
  - **RISE**: 雨の日は max(Δθ, 0)、ほかの日は0(段階27・38の P と同じ)
  - **NP_resid**: 雨の直後の各日について d − b_j × r、ほかの日は0。b_j は j = 1, 2, 3 ごとに、原点を通る最小二乗 d ≈ b_j r で、**ラベルを使わず解析集合の全圃場の全イベント**から1組だけ求める(主は120件、参考の108件では108件で求め直す)
  - **NP_rise_robust**: 上昇量 r ≥ 0.01 のイベントの後の日は d / r を [−1, 0] に切り詰めた値、r < 0.01 のイベントの後の日とほかの日は0
- 解析集合: **主は主ラベル120件**(土の物性を使わない)。参考は段階38の主の集合108件(bd と θ30 がある件)で、段階38と同じ分割(`make_splits` を同じ108件に当てる)。参考では段階38の NP・NP_rise の保存済みの結果(`outputs/stage38/partial_*.pkl`)を読み、乱数0の先頭10 fold を計算し直して一致を確かめる
- 分類器・分割: 段階38と同じ(MiniRocket 10,000、乱数0〜9 → StandardScaler(with_mean=False) → RidgeClassifierCV(logspace(−3, 3, 10) × n_train)、`make_splits(y, muniCd, 5, 20, 0)`)
- 置換検定: 市町村×年の中、置換 i は `default_rng([0, i])`、各200回、帰無分布は乱数10通りの平均。**主の4入力(NP・RISE・NP_resid・NP_rise_robust)の全体 AUC の p に Holm 補正**。参考の108件の入力も200回(記述)
- 差: 主の集合で RISE − NP、NP_resid − NP、NP_rise_robust − NP、NP − RISE。参考の集合で NP_rise_robust − NP_rise(段階38)と各入力 − NP。市町村単位のクラスターブートストラップ2000回(段階27・29・38と同じ)
- 記録: alpha が上限に張り付いた割合、b_1〜b_3 と回帰に使った日数、残差と上昇量の相関(日単位・圃場ごとの平均)、圃場ごとの平均で NP_resid と NP・RISE の Spearman、NP_rise_robust で除いたイベント数・日数と切り詰めた値の数、段階38の NP_rise と NP_rise_robust の上昇量との相関
- 感度分析(記述のみ、置換なし): b_j を各 fold の学習データだけで求めた NP_resid(乱数0〜9)の全体 AUC。参考(記述のみ、置換なし): NP と RISE の2チャンネル(MiniRocketMultivariate、段階27の PN と同じ構成)
- 読み方(判定は全体 AUC、D-007。W・B は出さない):
  1. RISE が95%点を上回り、NP − RISE の区間が0を含み、NP_resid が偶然の水準 → N_post の識別力は反応の大きさ(雨での上昇量)と同じ情報で説明できる
  2. NP_resid が95%点を上回る → 反応の大きさを取り除いても減り方に情報が残る。「排水の速さ」の解釈を支持する
  3. NP_rise_robust が95%点を上回る → 段階38で NP_rise が下がったのは主に小さな上昇量のイベントによるノイズだった
  4. NP − RISE の区間が0より上で、NP_resid も偶然の水準 → NP には RISE を超える情報があるが、線形の残差では取り出せない。非線形の関係の可能性として記述する
  5. どの入力も NP より下がり区間が0を含む → 差は検出できなかった、と書く(「同じ」とは書かない)
  - 95%点を上回るかは Holm 後 p < 0.05 で判断し、補正前の p も併記する。n ≈ 120 では差の区間が広くなりやすいので、結論は「差の証拠があるか」の形で書く
- 試運転(`--part trial`、乱数2・置換20・ブートストラップ100、`outputs/stage39/trial/`)はコードの確認と所要時間の見積もりだけに使い、設定は変えない
- 注意: N_post は段階29で同じデータから見つけた仮説で、段階38の結果を見た後の探索でもある(double dipping)
- 影響: `analysis/stage39/run_stage39.py`(新規。段階38・27・13・6 の関数を import、既存のファイルは変更しない)、`data/processed/stage39/`、`outputs/stage39/`
- 追記(2026-11-28、入力を作った後・AUC を計算する前): NP_resid と上昇量の相関は0にならなかった(日単位 Pearson +0.21、圃場ごとの平均で Spearman −0.33。NP は −0.93)。原点を通る回帰は切片が無いので残差と r の中心化した相関が0にならないことと、減少が大きな上昇量で頭打ちになる非線形性による。定義は変えずにこのまま評価し、レポートに明記する
